# Agent Note: Leon 在强制执行前以 shadow mode 评估模型路由

Status: implemented

[English](2026-08-24-leon-shadow-routing-preflight.md) | 中文

## Problem

Leon Automatic 过去根据提示词长度和标记选择本地层级，然后依赖提供方失败才进入 OmniRoute、Gemini 或 OpenAI。一次真实的长任务测试暴露了这种顺序的缺陷：本地模型运行超过一分钟后到达输出上限，继续请求仍使用该模型，随后才以 `CONTEXT_WINDOW_EXCEEDED` 失败。系统没有持久证据来说明，如果在发送前进行能力感知决策，是否会选择不同路由。

立即自动强制执行只会用一个尚未测量的启发式替换另一个。替代策略还必须区分请求容量与提供方健康状态，遵守本地优先隐私要求，只在价格已知时估算外部费用，并避免存储它所评估的内容。

## Decision

Web 部署保留当前自适应选择和故障转移行为，同时由 `adaptiveRouting.shadow` 在最终 `llm/stream` 边界安装被动预检。该边界能看到 agent loop 组装出的精确冻结请求，并且仍位于适配器消费之前。观察器原样调用下游 stream，异步解析候选能力，并追加一个 `llm/routing-shadow` 事件，记录所观察到的路由和它建议的路由。

候选身份、驻留位置、相对质量、部署优先级、冷启动 TTFT 基线和可选价格属于显式部署策略。上下文窗口、输出限额和输入模态来自已注册适配器的精确模型元数据。挂载 `ctx.tokenMeter` 时，当前请求压力来自该服务；只有未组合该服务的部署才使用保守的结构估算。决策会先为输出和工具循环增长预留容量，再把预计压力与各候选的上下文窗口比较。

外部路由策略是显式的。随附 Leon 配置采用 `fallback-only`：只要存在有能力的本地路由，就不建议外部路由；但当所有本地候选因容量、模态、健康、同一会话最近的容量失败或最低质量检查而不合格时，可以建议外部候选。路由优先级保留预期顺序，而策略实现不内嵌 Leon 的模型名称。

## Audit and privacy contract

持久事件包含 schema 版本、策略版本、随机请求关联 id、Turn 与 Step、实际路由、结构化计数、token 估算与预留量、候选能力摘要、有序拒绝原因代码、价格元数据完整时依据配置得到的预计费用、建议路由，以及 `wouldChange` 标志。它绝不包含提示词文本、系统文本、工具 schema、消息、凭据、提供方错误或这些内容的哈希。手动模型会话以及标题或压缩辅助请求不在观察范围内。

Shadow mode 没有执行权限。它不能改变提供方、模型、推理强度、重试、接纳或返回的 stream。能力解析和事件发布在带外运行；观察失败只会记录警告，实时请求保持不变。

## Health and capacity semantics

提供方健康状态是进程内且按路由隔离的。成功的终止响应会更新 TTFT 指数移动基线；在样本足够之前，每条路由使用显式冷启动基线。相对延迟可以把路由标记为 degraded，而 circuit 只有在连续提供方失败达到配置次数后才会开启。不存在会开启 circuit 的全局固定延迟阈值。

`MAX_TOKENS`、`CONTEXT_WINDOW_EXCEEDED` 和 `CONTEXT_LENGTH_EXCEEDED` 是容量结果，不是提供方健康故障。它们只针对同一 Session 和路由在有界冷却期内保留，使下一个相关请求可以避免重复已知容量不匹配，同时不会影响无关 Session 对该模型的使用。

## Alternatives considered

**立即让新建议成为实时路由器。** 不采用，因为该策略尚未在 Leon 的真实工作负载上积累分歧、误报、延迟和费用证据。Shadow mode 可以在不增加新故障路径的情况下生成这些证据。

**只保留现有提示词标记分类器。** 不采用，因为它看不到完整系统提示词、工具 schema、累计历史、输出预留、精确注册上下文窗口或最近容量结果，而这些正是已观察失败涉及的事实。

**把上下文溢出当作提供方宕机并使用现有故障转移 circuit。** 不采用，因为该提供方对较小请求可能完全健康；全局路由惩罚会让一个超大 Session 增加无关工作的费用和数据外传。

**记录提示词或提示词哈希供后续评估。** 不采用，因为原始内容会违反本地优先边界，而稳定哈希仍会暴露相等关系和字典攻击信息。结构化元数据足以支持本阶段。

**选择前用模型调用探测每个候选。** 不采用，因为探测会增加费用、延迟、潜在数据传输和副作用歧义。Shadow mode 只使用精确注册能力元数据作为候选输入。

## Verification

单元测试固定了本地优先选择、发送前预计上下文溢出、不会污染 circuit 的同一会话容量处理、外部拒绝行为、价格估算、重复路由拒绝和配置默认值。集成测试让带 agent-loop 标记的请求经过真实 `llm/stream` waterfall，证明原始路由和终止 chunk 未改变，等待持久 shadow 事件，并验证其中没有提示词文本。生成的持久化目录包含 `llm/routing-shadow`，Web bundle 测试固定随附候选目录和 shadow 策略。

## Consequences

Leon 现在能够为更好的预检生成可测量证据，同时保留用户当前正在测试的行为。Session 导出可以比较实际路由和建议路由而不暴露对话内容，记录的拒绝代码可以区分不可用、能力不足、隐私阻止、不健康和最近容量受限的候选。

该建议尚未作为专用 dashboard 卡片显示，也不会改变实时模型。后续强制执行决策需要来自真实 Session 的证据、显式误报与费用阈值，以及单独审查的 UI 和控制约定。运行时健康状态有意保持在进程内；跨进程持久健康状态需要独立的遥测保留策略，不能静默把 Session 日志变成全局 circuit-breaker 数据库。
