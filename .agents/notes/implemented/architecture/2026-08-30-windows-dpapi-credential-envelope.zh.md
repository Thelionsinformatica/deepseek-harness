# Agent Note: Windows DPAPI 凭据封套

Status: implemented

[English](2026-08-30-windows-dpapi-credential-envelope.md) | 中文

> 范围：为 Windows 本地凭据文档增加静态保护，同时不削弱[凭据边界](2026-07-30-credential-boundaries-and-atomic-registration.zh.md)中记录的原子注册与同用户边界。

## 问题

`credentials-local` 过去在 Windows 上以明文保存其逻辑 version-1 YAML 文档。文件 ACL 将普通访问限制在当前用户、管理员与 SYSTEM，但意外复制、诊断包或离线磁盘读取仍可能直接暴露提供方名称与值。启动和写入路径还需要一条统一的迁移规则，不能在没有告警的情况下把有效明文源替换成无法读取的加密文档。

## 决策

在 Windows 上，提供方把完整的 version-1 逻辑文档存入 version-2 YAML 封套，并使用带包专用可选熵的 Windows DPAPI `CurrentUser` 范围保护它。封套只暴露版本、保护标识符与规范 base64 载荷；凭据引用、记录、值、注释和格式全部保留在受保护载荷内。

保护采用失败关闭。每个新数据块在原子替换之前都会立即解密并与源字节比较。保护、解密、UTF-8、比较或解析任一失败都会中止激活或写入，并保持磁盘上的上一份文档不变。凭据字节只通过标准输入和标准输出传给固定的 Windows 内置 PowerShell 辅助程序，不进入 argv、子进程环境或诊断信息。

启动时可把已识别的预发布扁平布局和 version-1 文档作为迁移源。它在现有跨进程写锁内重新读取、验证逻辑文档、保护并验证，然后原子提交 version-2 封套。竞争启动若发现另一进程已经提交的封套，就直接使用而不再重写。运行中的明文降级会被拒绝，并保留上一份良好快照，直到重启能够执行带锁迁移。

POSIX 继续在 `0700`/`0600` 下保存 version-1 文档；这项变更不声称提供可移植的跨平台钥匙串。DPAPI 是防止离线检查和其他 Windows 用户读取的静态边界，不是针对已经以同一 Windows 用户运行的进程的边界。同用户工具可以调用 DPAPI，真正需要隔离的部署仍需使用代理式钥匙串或服务，使这些工具无法调用解密操作。

## 验证

提供方测试套件覆盖受保护读写、明文迁移、并发迁移、畸形封套、不支持的保护标识符、非规范载荷、保护与验证失败、运行中降级拒绝、不含机密的诊断、输出大小限制，以及 Windows 上真实的合成 DPAPI 往返。既有原子写入、监视器、记录、排空与注释保留测试通过注入的确定性保护器运行，因此逻辑文档保证仍被实际覆盖。

## 曾考虑的替代方案

- **逐个加密值**——不采用，因为凭据名称、记录元数据、注释和文档结构仍会保持可读，并且每条编辑路径都必须感知加密标量。
- **只依靠文件 ACL**——作为纵深防御保留，但不作为唯一静态控制，因为复制和离线读取可能脱离预期 ACL 上下文。
- **把 DPAPI 描述成模型隔离**——不采用，因为工具与提供方以同一 Windows 用户运行；操作系统允许该用户调用相同的解密原语。
- **静默回退到明文**——不采用，因为保护不可用时应停止操作，而不能在没有通知的情况下让凭据存储降级。

## 后果

Windows 凭据文档不再是可自行携带的明文制品，也不得视为与机器无关的备份。Leon 的备份流程继续排除凭据保险库，因此恢复后会重新登记凭据。每次受保护的读取或写入都会启动一个有时限的本地辅助进程，使罕见的凭据管理操作增加少量延迟，同时保持既有内存提供方 API 不变。Windows 上的明文 version-1 文档会在下一次成功启动提供方时迁移；如果保护无法完成并验证，原始字节保持不变。
