# Agent Note：Leon 可解析的故障转移级联

状态：已实现

[English](2026-08-25-leon-resolvable-failover-cascade.md) | 中文

## 问题

Leon Automatic 只能把失败提供方替换为首个已配置候选项。如果该中间候选项因适配器或模型不可用而无法解析，恢复流程会回到失败提供方的普通重试策略。随附的本地与回环路由没有显式策略，因此这条路径可能把已经失败的请求重复五次，而且永远无法到达后续已配置的故障转移路由。

## 决策

API 代理现在把故障转移候选项解析为有界的提供方级联。当中间候选项无法解析时，它的提供方会成为下一次已配置选择的失败边。已访问提供方集合会拒绝循环，16 跳上限会防止错误策略生成无界链并占用恢复 waterfall。只有最终可解析的替代路由会持久化为 `llm/failover`；被跳过的候选项不会收到请求。

随附的 Ollama 与 OmniRoute profile 都声明了 `maxRetries: 1` 的 normal 重试策略。自动模式仍会在该策略之前尝试跨提供方替换。一次重试是手动选择或部署中没有任何已配置替代路由可解析时的最终有界恢复。由 settings 管理的 Gemini 配置与凭据保持不变。

## 已考虑的替代方案

**首个候选项无法解析时立即委托。** 已拒绝，因为可选的中间适配器不应阻止后续已配置的直连提供方接管请求。

**在接收每个 prompt 前探测所有提供方。** 已拒绝，因为目录或健康探测不能证明请求能够执行，会给健康路径增加延迟，并重复权威模型请求失败边界的职责。

**级联耗尽后把原提供方重试五次。** 已拒绝，因为重复连接失败会隐藏配置问题，并使界面看起来已经停滞。一次有界重试可以容忍短暂瞬态问题，同时避免恢复长时间等待。

## 测试

Host 集成测试证明：不可用的中间适配器会被跳过；下一个有效路由会接收同一请求；日志只记录成功的替代路由；提供方循环会委托一次且不会挂起；取消会停止级联且不会委托更多工作；手动选择绝不会跨提供方；有效的自动替代仍会绕过普通重试。Base 与 Web 组合测试固定了一次重试的本地策略和已部署故障转移链。

## 后果

Leon Automatic 可以越过不可用的 OmniRoute 或直连提供方适配器继续执行，而不会被困在其后。用户仍会看到一条持久路由切换通知，其中命名真正接管请求的路由。如果所有已配置替代路由都不可用，原本的本地或回环路由在本轮明确失败前最多只会进行一次符合条件的重试。云端使用仍受部署中显式故障转移边限制。
