# Agent Note: Leon separates history, memory, knowledge, and explicit targets

Status: implemented

English | [中文](2026-08-28-leon-context-continuity-and-target-preservation.zh.md)

## Problem

Leon could answer that it had learned nothing after checking only empty workspace or personal-memory stores even when prior session logs and an external `.leon/knowledge` base existed. A default filesystem MCP server exposed only the Leon source repository; when an explicitly requested external path was denied by that tool, the model silently substituted the repository and reported unrelated findings. Session full-text search also remained disabled in the Web composition, so completed work was not discoverable through a model-facing history query.

Retrieved session text can itself contain stale or adversarial instructions. Without an explicit trust boundary, a historical snippet could claim authority to replace the user's current target. The earlier access guidance also grouped technical failures with user, approval, sandbox, permission, and policy denials, so a denial could incorrectly trigger a different tool or equivalent path.

The adaptive-routing shadow independently treated the active model's declared quality and the number of always-visible tool schemas as evidence that every request required expert quality. That made the passive recommendation saturate on simple prompts and confused catalog size with task difficulty.

A local model could also stop after emitting only internal reasoning or blank text. The adapter preserved that content correctly, but the agent then found no tool call and closed the turn as completed, leaving the user with a thinking row and no answer. Repeating the request verbatim was less reliable than a logged continuation that explicitly required an observable tool call or final response.

## Decision

Leon now treats session history, workspace memory, personal memory, and `.leon/knowledge` as separate sources. Its persona requires consulting the applicable sources before answering what was learned or completed, and an empty result is scoped only to the queried source. The `leon-knowledge-base` skill adds a bounded read-only `search` operation over `index.md` and `wiki/**/*.md`; it excludes raw evidence, logs, and schema files, enforces canonical-path containment, limits files and output, filters common Portuguese recall words before ranking, and accepts an explicit external workspace without importing it into another memory domain.

Stable cross-tool instructions live in the prompt section owned by each package, while Leon's persona carries its identity, source selection, privacy, target, denial, web, and reminder policy. Configurable query bounds remain in the tool schema and concise guidance. The assembled preset has a 32,000-byte static-context ceiling so catalog growth cannot silently consume local-model capacity without an E2E failure.

The Web composition stores the derived session index under the DSH home and opens SQLite only on the first search. Leon exposes `session_search` for prior work plus the query-only `current_session_search` for bounded recovery after compaction or a model change. The latter always targets the caller and stops before the invoking step, without exposing session ids, raw-event reads, traces, or filter controls. Windows drive paths are matched case- and separator-insensitively while the provider still receives only observed authorized spellings. Other presets retain the five general operations through the `enabledTools` option.

The fixed repository-root filesystem MCP example remains available in configuration but is disabled in Leon's default catalog. Native filesystem and PowerShell tools retain authorized absolute-path access, and the persona requires preserving the user's explicit target across turns. Leon may diagnose a technical access failure on that same target, but a user or policy denial stops the action. Neither outcome is evidence that the target does not exist.

`session_search` prompt guidance and every non-empty result label retrieved history as untrusted data rather than instructions or authority. Only a direct user request changes the active target. Leon distinguishes a retryable technical failure from a user or policy denial: a denial stops the action without retrying, changing tools, bypassing, escalating, or selecting an equivalent path. The knowledge and Windows Skills apply the same rule. An external knowledge workspace remains valid when the direct user message names or confirms its exact absolute path; history, memory, documents, and tool results cannot grant that authority.

Automatic external-failover consent records the newest durable session event that it covers. Any later protected local retrieval—including files, shells, code navigation, memory, session history, images, attachments, browser/desktop state, Skills, and subagents—invalidates the grant. An already-active external failover is revalidated before every step and returns to its last local route when consent is stale; a second check closes asynchronous assembly races. Public-only `web_search` and `web_fetch` results do not consume the grant. Saving consent again explicitly covers the expanded context; restarting the Host still revokes every grant.

The passive routing shadow now derives minimum quality only from structural request pressure: input tokens, message count, and image modality. Visible tool count still contributes to tool-loop token reserve, but neither the active route's declared quality nor catalog size raises the requested quality tier. The automatic-model safety hold remains unchanged: all automatic local tiers continue to use Qwen 3.5 9B until specialists pass long-autonomy acceptance.

The shared failure-recovery policy observes `agent/turn-stopping` and treats reasoning plus whitespace or invisible Unicode format characters as missing final output. Its compatibility default is zero, while the base deployment explicitly enables one logged same-turn continuation on the active route; deployments may choose at most three. The continuation instructs the model to execute the required tools or provide a user-facing answer without restating its plan. Non-blank text, tool calls, extension blocks, and `max-tokens` outcomes retain their ordinary semantics. Recovery messages are counted after the latest direct user input. Once the configured allowance is exhausted, an `llm/stream` wrapper converts another empty successful finish into the stable `NO_FINAL_RESPONSE` error finish, without throwing from or short-circuiting other turn-stopping listeners. This continuation does not select another model or authorize an external provider.

Knowledge queries use the bounded `knowledge.mjs search` helper with the exact workspace named by the user before native filesystem discovery. They do not replace an explicit absolute workspace with `.`, recursively enumerate `.leon/knowledge`, or read `raw/` wholesale; only a source linked by a relevant wiki page may be opened to confirm an important claim. A prior-session query that returns no matches receives one shorter retry with one or two distinctive terms before that source is reported empty.

Leon now mounts `knowledge_status` and `knowledge_search` as dedicated model-facing tools backed by the same fixed helper contract. While a directly authorized external knowledge target is locked, the explicit-target policy blocks generic filesystem, shell, editor, image, and terminal tools from operating as an alternate route. A knowledge turn may complete successfully only after every configured required tool has a durable root-model `tool/call` and a final successful `tools/result` for every authorized target in the current turn. Nested calls, direct extension calls, failed results, and post-execute rewrites do not satisfy the contract. Durable events reconstruct progress after a plugin remount; one bounded correction asks the model to continue, after which a still-incomplete turn ends with `REQUIRED_TOOLS_MISSING` instead of a false success.

## Verification

Focused Vitest suites cover bounded knowledge search, natural-language ranking, workspace isolation, redirected-path escape prevention, selectable session-query registration, Windows path aliases, current-session cutoff, and invalid configuration. The required-tool suite additionally covers durable root calls, final-result rewrites, multi-target completion, external-call false positives, remount reconstruction, bounded correction, and the stable terminal error. An adversarial history fixture tries to redirect the target to another drive; the rendered result places the trust boundary first and the provider request remains fixed to the caller workspace. Failover tests inject synthetic secrets into protected local retrieval sources and prove that stale consent makes zero external route-resolution or next-step calls; they also cover active-route races, fresh explicit consent, and public web results. Recovery tests cover reasoning-only and whitespace-only continuations, valid text and tool-call completion, `max-tokens`, the durable per-turn limit, and the explicit terminal error. Routing tests cover simple prompts with large tool catalogs and long-context escalation. Leon preset E2E checks the two compact history tools, absence of the misleading fixed MCP namespace, presence of native absolute-path-capable tools, trust and denial instructions, exact-workspace knowledge workflow, and the conservative static-context budget.

Visible acceptance exposed two real defects before the final pass: the first run reached the dedicated knowledge tools but later drifted back to generic `read` and `glob`; the second emitted only a plan and stopped without a tool call. Those failures drove the deterministic generic-tool block and the required-tool completion contract. After rebuilding and restarting the host, a fresh Leon Automatic session used one `knowledge_status` and seven `knowledge_search` calls on an explicitly selected external `.leon/knowledge` root, confirmed exactly five active sources, used no generic filesystem or shell tool, produced a user-facing answer, stayed on local Qwen 3.5 9B, and displayed estimated API cost `US$0.00`. Functional acceptance passed, but the run took 71 seconds and consumed about 103K input tokens / 49% of the context, so repeated-search efficiency remains a measured improvement area rather than a claimed success. The focused 75-test set, lint, runtime closure, workspace constraints, Cordis config verification, focused Leon preset E2E, and the host library build completed successfully.

## Alternatives considered

**Copy the external knowledge base into personal or workspace memory.** Rejected because it would erase provenance, mix privacy domains, duplicate source material, and make correction or deletion ambiguous.

**Hard-code an operator-specific workspace as a global filesystem root.** Rejected because a private machine-specific path is not portable and should be selected explicitly for the relevant task.

**Add a standalone `--authorized` switch to the knowledge script.** Rejected because the script does not receive authenticated conversation provenance; the model that supplies a path could also supply the switch. Authority therefore stays at the agent boundary that can distinguish a direct user message from retrieved data.

**Expose every session-query operation to Leon.** Rejected because prior-session discovery plus a query-only current-session recovery tool preserve local context budget; exact event reads and traces remain available to profiles that enable them.

**Fail over to a cloud model after filesystem access denial.** Rejected because `ACCESS_DENIED` is a tool/authorization failure rather than a provider outage and must not silently cross the local-to-external privacy boundary.

## Consequences

Leon can discover prior work and recover earlier context in its current session without pretending that all knowledge lives in one store, and it keeps the target named by the user instead of falling back to the repository. Historical text remains usable evidence without becoming a control channel. A denial ends the attempted action instead of provoking tool shopping. A local model that plans without acting receives one bounded correction and can no longer leave the task silently completed; if it still omits the required evidence, the turn fails visibly rather than being reported as complete. The history database is derived and rebuildable rather than canonical. External knowledge remains opt-in per exact path and is not automatically injected into every conversation. External fallback remains available, but protected local retrieval requires the user to save consent again for the expanded context. The dedicated knowledge surface protects provenance and target containment, although query-count efficiency still depends partly on model behavior and needs a separate acceptance budget. The two-tool history surface favors local context economy over event-level forensic navigation, while other presets can opt into the broader API.
