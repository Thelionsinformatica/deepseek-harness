# Agent Note: Leon 在全局完成声明前要求证据

Status: implemented

[English](2026-08-29-leon-completion-evidence-guard.md) | 中文

## 问题

即使同一轮次仍包含待处理 todo、失败工具、非零命令退出码，或最终响应声称存在但实际不存在的输出文件，Leon 仍可能以“全部正常工作”之类的全局声明结束普通轮次。目标完成审计器只保护显式的目标完成路径，因此最终 assistant 文本可以绕过它。仅靠提示词指令无法把会话事件日志转化为强制执行的完成条件。

## 决定

一个 Leon 专用的完成证据插件在 `agent/turn-stopping` 监听，并且只检查肯定、无局部范围的强全局完成声明。句子级分类不会阻止否定、条件、引用、不确定、部分完成或明确受阻的报告，同时免责声明也不能隐藏后续肯定声明。对于候选声明，插件通过持久会话事件重建当前轮次：最新 todo 状态、配对的工具调用与工具结果、命令退出码，以及最终响应中断言存在的绝对产物路径。后续成功结果仅在工具名称与持久参数载荷完全相同时解决早先失败；缺失或矛盾的证据仍然是未解决缺口。

当声明存在未解决缺口时，插件会阻止轮次停止，并通过普通 inbox／用户消息路径注入一条持久的插件来源纠正消息。完整纠正消息受 UTF-8 字节上限约束，文件系统检查受数量上限约束；超出部分会作为证据缺口报告，而不会静默信任被省略的详情。该消息要求 Leon 完成且验证工作，或把结果如实报告为部分完成或受阻。如果 Leon 在已配置的纠正次数用尽后再次重复无证据支持的全局声明，插件会以稳定代码 `COMPLETION_EVIDENCE_UNSATISFIED` 失败关闭。

在 Leon Automatic 中，这条持久纠正消息会为重试选择已配置的本地 expert 路由，并使用 high 推理强度。它不会授权外部 API 路由、改变提供方数据驻留策略，也不会把无证据完成当作提供方不可用。手动模型选择保持手动。现有目标完成审计器仍作为显式目标完成请求的独立第二道屏障。

## 验证

聚焦的完成证据测试固定对抗性 PT/EN 分类、待处理和进行中的 todo、未解决的精确操作失败、非零命令退出码、缺失的断言产物、产物检查数量，以及包含多字节字符的完整 UTF-8 恢复消息上限。测试还固定相同操作的成功重试会解决对应失败、不同操作不能隐藏失败、如实的部分完成或受阻响应可以停止，以及重复无证据声明会返回 `COMPLETION_EVIDENCE_UNSATISFIED`。一个无密钥 Loader 快照会启动真实组合，并记录持久且模型可见的纠正消息与如实替换响应。

自适应路由测试固定该纠正消息在 Leon Automatic 中只选择已配置的本地 expert 路由和 high 推理强度。测试还固定手动选择不变，且该纠正消息不会启用外部提供方。现有目标测试继续覆盖独立的完成审计器。

## 考虑过的替代方案

**仅依赖系统提示词。** 已否决，因为指令可以影响措辞，却无法把最终声明与权威会话事件比较，也无法阻止轮次停止。

**只使用目标完成审计器。** 已否决，因为普通最终响应无需调用目标完成工具，而这正是本决策关闭的绕过路径。

**保留并检查完整模型流。** 已否决，因为推理与部分流 token 不是权威的用户可见结果，会增加保留成本，而且仍需与持久工具证据进行核对。

**把该行为加入 `failure-recovery-policy`。** 已否决，因为重复工具执行失败与无证据完成属于不同策略。Leon 专用插件负责声明分类与证据核对，不会改变其他组合的一般恢复行为。

## 后果

与持久轮次记录矛盾的强全局完成声明不能再作为 Leon 轮次的最终状态。由于验证发生在 `assistant/message` 提交之后，第一次流式声明可能已经可见；同一轮次随后会收到具体的纠正续行，一次本地 high 强度重试可以在守卫失败关闭前修复证据。如实的部分完成与受阻报告仍然可用，手动模型控制与外部数据驻留保持不变，显式目标完成仍会经过独立审计器检查。

该插件有意只识别范围狭窄的强完成语言与绝对产物声明。它不会证明成功工作的语义质量、取代特定领域测试，或推断未被提及的产物是否应当存在；这些仍由任务专属验证与目标审计器负责。
