# Agent Note: 记忆导入的预验证和重试

Status: implemented

[English](2026-09-06-memory-import-preflight.md) | 中文

## 问题

导入可能先写入前面的域，随后才发现后面的目标缺失或版本不兼容。分开的 get 和 put 操作也可能覆盖在两次操作之间由并发导入创建的 ID。

## 决策

记忆连续性模块在首次写入前复制并验证快照，并解析所有目标。它拒绝重复的域名、目标名称以及同一域内重复的记录 ID。插入使用 KvTable.mutate，确保只写入缺失的 ID。

存储错误会将导入拒绝为未完成。先前的写入可能已提交；重试同一快照会跳过已有 ID。日志持久化由调用方负责，失败时不返回成功条目。

## 考虑过的替代方案

**全局回滚：** 表接口没有跨域事务。补偿性删除可能抹掉合法的并发更新，因此导入不承诺回滚。

**先 get 再 put：** 这种方式无法在并发导入时保证只插入。条件修改将检查和插入作为一个整体处理。

## 后果

故障注入示例仅在运行编译后 JSON 后端的临时子进程中拦截文件系统调用。它在临时文件部分写入后、重命名前或重命名后退出。新的 Loader 进程重新打开预期的完整旧状态或新状态；测试观察到遗留临时文件，但不会将其视为已提交数据。这是确定性的进程故障覆盖，不是物理断电测试。

重启测试包括在写入得到确认且快照导出后立即退出进程。关闭标记不存在证明释放流程被跳过；新进程验证谱系和幂等性。这不覆盖写入尚未完成时的终止或物理断电。

磁盘示例通过编译后的 JSON 后端和域层验证正常进程重启及恢复。独立进程拒绝人为损坏格式的文件，不修改该文件或原始域。写入期间断电和多个进程同时写入仍未测试。

无效目标不再导致部分导入。存储故障仍可能导致部分导入，因此恢复需要修复存储并重试，不能假设操作具有全有或全无的语义。已有 ID 即使内容不同也会保留。

测试覆盖写入前拒绝、存储失败后的重试，以及使用内存适配器的并发导入。无密钥示例通过 Loader 启动编译后的包，导出文件并重新导入，拒绝缺失目标并验证服务释放。注册使用 Cordis provide，而非赋值给未注册的上下文属性。这些测试不能证明真实磁盘崩溃恢复、多进程并发或真实模型切换。
