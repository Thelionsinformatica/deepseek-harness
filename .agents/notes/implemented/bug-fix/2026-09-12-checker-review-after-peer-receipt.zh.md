# Agent Note: 原生同伴消息收到后的 checker 任务审核

Status: implemented

[English](2026-09-12-checker-review-after-peer-receipt.md) | 中文

## 问题

v1 import-lab 完成审核器接受包含当前产物摘要的工具结果。这允许 checker 在收到同伴发现之后完成任务，即使它唯一一次验证发生在收件之前。最终任务验证器正确拒绝缺少收件后验证的情况，但已完成的任务状态掩盖了缺失的交接动作。产物通过和任务看板完成并不能证明协作。

## 决策

可选 `requirePeerReviewAfterReceipt` 增加单独的 v2 完成契约，默认值为 false。它要求[宿主分配的任务组合](../feature/2026-09-12-host-mission-composition.zh.md)。只有宿主绑定的 checker 会话必须提供成功的 `mission_verify` 结果，其中 `passed: true` 且摘要对应当前产物，调用时间晚于与 Lead 日志匹配的原生同伴收件。显示名称不能选择该职能。researcher 的完成以及关闭该选项时的 v1 行为保留现有证据规则。

任务审核器与最终任务验证器共享同一个提取出的同伴证据谓词。最终成功标准保持不变：当前产物通过、恰好两名成员、至少两个已完成的原生任务、同伴收件及收件后工作者验证。checker 完成被拒绝时报告 `MISSION_CHECKER_PEER_REVIEW_REQUIRED`，不运行工具、不改变任务修订，也不完成另一参与者的工作。诊断明确要求在同伴收件之后执行当前验证；它不改变模型提示词。

## 考虑过的替代方案

**将任务完成视为充分证据。** 这会移除独立协作条件，并错误地批准缺乏支持的结果。

**自动验证或完成任务。** 这会伪造代理行为或绕过原生任务所有权，而不是修复完成准入。

**将规则应用到所有现有配置。** 这会悄悄改变冻结的基线。实验标志允许比较，而不重新分类以前的尝试。

## 后果

即使当前产物通过，审核器也拒绝收件前、陈旧或失败的验证。只有绑定的 checker 接受更强契约。预算、预留分配、截止时间、提示词、正常配置以及历史尝试均不变。这是有限的执行契约修正，并不宣称模型一定遵循诊断，也不宣称集体优于单独执行。

## 验证

聚焦测试使用原生会话、工具、任务、成员、同伴投递及 JSONL 持久化，并使用脚本适配器。测试证明拒绝时任务不变、当前收件后证据被接受、最终成功标准不变、陈旧及失败证据被拒绝、交换显示名称不影响职能、researcher 兼容以及 v1 行为。测试还拒绝未启用宿主组合却启用该选项的配置。这些测试不证明外部模型推理或 GPU 性能。
