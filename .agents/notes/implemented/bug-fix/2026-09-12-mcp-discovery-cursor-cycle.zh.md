# Agent Note: 拒绝循环的 MCP 工具发现

Status: implemented

[English](2026-09-12-mcp-discovery-cursor-cycle.md) | 中文

## Problem

MCP 服务器可以在空页之间重复返回 `tools/list` 续传游标，而不触发重复工具检查。同步会一直等待，启动或排队的列表更新也无法结算。

## Decision

[mcp-client](../../../../packages/mcp/mcp-client/README.zh.md) 在每次同步中记录非空续传游标，并在请求下一页之前拒绝重复游标。这是来自[上游提交 594305ce](https://github.com/deepseek-ai/deepseek-harness/commit/594305ce19765086472c6ef95c09c3f2a70ce37c)的定向修复，不迁移会话格式或框架。游标记录仅属于当前操作：后续通知或重连可以合法地复用游标。

工具发现保持事务性。被拒绝的获取操作不会更改已有注册或其可调用执行器；严格启动会报告错误并关闭失败的客户端。后续工具发现成功时会正常替换世代。诊断中不包含不透明的游标值。

## Alternatives considered

**依赖重复工具名。** 空页以及工具名称各不相同的页面仍可能循环。

**跨同步保留游标。** 服务器可能为更新后的列表使用相同分页标记，因此全局记录会拒绝合法恢复。

**新增页数或时间限制。** 这会引入与重复游标缺陷无关的部署策略。持续返回不同游标的情况仍是明确限制，而不是被赋予任意上限。

## Consequences

重复游标会使工具发现以错误结算，且不会发布部分工具世代。游标记录占用的内存随一次同步中不同页面的数量增长；请求超时及无限不同游标链的行为保持不变。单元及生命周期回归测试覆盖立即重复、多页循环、保留的可调用工具、空终止游标、后续游标复用、致命启动失败以及通知恢复。CLI（命令行界面）快照通过 headless 配置与本地 stdio MCP fixture（测试前置数据）执行严格启动，不需要模型推理（inference）。
