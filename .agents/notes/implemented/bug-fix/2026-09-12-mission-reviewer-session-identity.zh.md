# Agent Note: 任务预留额度要求宿主绑定会话身份

Status: implemented

[English](2026-09-12-mission-reviewer-session-identity.md) | 中文

## 问题

实验执行器允许使用审阅者显示名称及其前缀或后缀取得权限。因此，模型控制的名称可能在没有审阅授权的情况下占用最终推理额度。

## 决定

宿主以原生、持久化的队友 ID 配置 `reviewReserve.reviewerSessionId`。执行器安装时复制该策略。允许任何推理（inference）或工具执行之前，执行器检查该 ID 属于本任务的持久化成员名单，且不是 Lead、失败成员或仍在创建中的成员。非活动队友仍可通过原生机制恢复。原生成员身份检查仍要求完全匹配的实时 Agent（智能体）对象。显示名称不授予审阅权限。

旧的 `reviewerName` 配置被拒绝；运行时不转换名称，也不修改冻结的实验室 manifest（元数据清单）。宿主必须在使用预留额度之前创建并绑定审阅者。普通组合保持不变，执行器不会自动完成任务、增加预算、修改标准或授权云端回退。STOP 和截止时间仍具有权威性。

源码解析映射包含三个实验性 Loader 入口和 Web 访问 UI 入口。包文件检查包含明确的私有实验室构建包和共享分片，但不允许正式 CLI（命令行界面）引入实验性运行时依赖。

## 考虑过的替代方案

**严格匹配显示名称。** 这只能消除前缀和后缀缺陷；模型仍可选择拥有特权的精确名称。

**独立的角色或任务数据库。** 原生会话身份和现有成员名单已提供所需的授权依据。复制它们会增加协调和恢复歧义。

**自动迁移旧实验室配置。** 从名称推断授权会改变冻结的实验，且无法证明宿主选择了该成员。

## 后果

名称伪装和调用方持有的可变配置对象不能授予审阅预留额度。缺失、失败、其他团队、创建中或 Lead 的 ID 均在消耗推理调用前被拒绝。使用名称分配的实验需要明确的宿主集成；此补丁不声称完成了该启动流程，也不解决准入被拒绝后的重复宿主反馈。

## 验证

任务控制测试覆盖持久化队友恢复、精确名称及前后缀伪装、配置变更、并发额度预留、无效审阅者组合、STOP 和预算保留。fixture（测试前置数据）在准入前通过脚本响应创建并恢复会话；这些测试证明现有会话的授权机制，不证明真实模型能在任务预算内完成启动。headless Loader 场景独立记录未绑定审阅者 ID 时任务受阻、准入调用为零且导入策略不变的结果。这些测试不能推断真实模型性能。
