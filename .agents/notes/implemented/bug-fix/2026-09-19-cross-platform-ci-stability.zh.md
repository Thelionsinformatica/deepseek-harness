# Agent Note: 跨平台 CI 稳定性缺口

Status: implemented

[English](2026-09-19-cross-platform-ci-stability.md) | 中文

## 问题

Linux 与 Windows CI 在多个位置与本地检出结果不一致：绝对路径只按当前主机语义解释，产物声明只识别 Windows 路径，Windows 临时工作区可能被误判为重定向，并发 DPAPI 子进程启动可能超过超时，而 SQLite 重试测试的预算不足以承受插桩后的 Windows 运行。Web 快照夹具还依赖在线模型目录、Windows 上不可用的 Bash 展示器、构建后才生成的 API remote 模块以及未声明的加载器夹具依赖。

## 决定

路径验证现在无论当前主机为何，都同时接受 POSIX 与 Windows 绝对路径语法。导入验证改为比较规范化最终路径与“规范化父目录加请求 basename”，既保留重定向检测，又不拒绝 Windows 短路径和长路径别名。Windows DPAPI 调用在进入有界子进程阶段前串行化。SQLite 重试测试保留原有重试断言，同时采用适合插桩运行的预算。

Web 回放测试使用仅含 header 的本地模型目录，在 Bash 不可用时注册仅测试用终端展示器，在源码级 dashboard 测试中模拟生成的 API remote，显式声明夹具依赖，并更新为当前已审查快照。

文档构建现在每个输出目录只发射一次原始 Markdown 投影。VitePress MPA 模式会在同一进程中重复调用 `buildEnd`；后续调用现在复用第一次发射结果，不再把这些已生成的 twin 误判为外部构建文件冲突。

## 验证

最终完整单元测试通过 15,047 项，跳过 79 项。快照基线通过 113 项，跳过 42 项。会话、策略、查询、完成声明、Windows 持久化、DPAPI、agent-team、Web 回放和 dashboard 的聚焦测试均通过。类型检查、lint、构建、产物门、Windows 阻塞门以及连续两次 MPA 文档构建均通过。差异空白检查通过。

仓库级标准覆盖率阈值仍是独立的既有质量债务；本次改动没有削弱或绕过该门。

## 考虑过的替代方案

大范围平台跳过会隐藏真实的可移植性缺陷。全局增加超时会掩盖竞争而不是约束它。在源码级测试中生成 remote 模块会让单元测试依赖构建顺序。也拒绝了大范围覆盖率排除，因为那会重新定义质量契约，而不是提高稳定性。

## 后果

受影响的 CI 路径在 Windows 与 Linux 上具有确定性，本地回放测试不再需要付费推理，Windows 凭据保护避免并发 PowerShell 启动竞争。正常运行配置、模型路由、凭据和用户数据均未改变。
