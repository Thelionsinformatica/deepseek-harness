# Agent Note: 完成审查证据与待办事项顺序

Status: implemented

[English](2026-09-20-completion-incomplete-evidence-gate.md) | 中文

## 问题

审查员可能接受不完整的执行记录。审查待办还要求在启动审查前就标记完成，诱发不实的待办完成声明。

## 决策

下文的外部写入限制已部分被[产物新鲜度检查](2026-09-21-completion-audit-boundaries.zh.md)取代：当前回执重新检查实际交付给审核器的文件，但不声称锁定工作区。顺序和分页证据规则仍然有效。

显式 review 操作不改变目标或待办状态。PASS 仅能在同一轮次、相同目标修订、待办内容不变且没有其他工作工具介入时复用。完成目标仍要求待办已完成。结果返回审查会话和有长度限制的摘要；持久回执不保存内容，并通过哈希绑定原始证据区间。

超长证据按现有单次交付字符上限分页。宿主必须交付每一页才能接受 PASS。访问权绑定到确切的审查员身份，并在审查结束时释放。父会话调用和结果以及直接子会话执行记录来自实时会话和可选持久化，而非模型选择的路径。原始记录保持完整。

## 考虑过的替代方案

自动完成审查待办会掩盖未完成的工作。更新待办后再次调用审查员会重复产生费用。静默截断证据会导致缺乏依据的批准。因此宿主提供显式审查，并拒绝陈旧或未交付的证据。

## 影响

专项测试和 Loader 测试覆盖顺序、新鲜度、分页交付、访问过期和输出上限。ACP 应用快照验证待办仍未完成时进行审查、随后完成待办且只调用一个审查员的流程。分页对大量证据增加读取调用。覆盖范围仅限直接子会话；缺少持久化会明确标注。交付不代表理解，同轮次回执复用无法发现绕过 agent 工具的外部文件写入。真实模型证据与这些确定性测试分开记录。
