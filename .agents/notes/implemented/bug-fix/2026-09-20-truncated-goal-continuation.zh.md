# Agent Note: 截断后的目标续行

Status: implemented

[English](2026-09-20-truncated-goal-continuation.md) | 中文

## 问题

目标驱动器在 `max-tokens` 时停用续行，却保留 active 的持久目标。因此，输出截断会留下未完成且无法自动继续的工作。

## 决策

输出截断设置现有的检查点义务，而不是停用续行。现有 idle 调度器只有通过 phase、启用状态、revision 和持久轮次上限检查，才接纳下一个编号轮次。它保留会话历史，不会将任务标记为完成。提供方错误与取消保持原有行为。

## 考虑过的替代方案

**提高输出上限：** 这只会推迟中断，而不是从中恢复，并会改变模型资源使用量。

**增加独立重试循环：** 这会重复准入与取消逻辑，并可能绕过轮次上限。

## 影响

续行可能在现有轮次额度内消耗更多模型调用。没有新增进度检测器或无限重试。使用脚本模型的真实循环测试验证历史保留、额度耗尽以及截断轮次结束前的暂停；它们不证明真实提供方恢复，也不证明已部署到运行中的服务。
