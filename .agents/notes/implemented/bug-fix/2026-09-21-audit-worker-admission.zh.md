# Agent Note: 审计工作 agent 的证据与请求准入

Status: implemented

[English](2026-09-21-audit-worker-admission.md) | 中文

## 问题

工作 agent 可能在没有执行任何检查的情况下结束审计生成，在只读提示词下仍获得写入工具，或在开展有效工作之前超出模型上下文。这些失败不应变成被接受的发现或无限重试。

## 决策

宿主配置的 `evidenceTools` 添加可选证据评估，与子 agent 的实际停止原因分开。评估只使用当前激活后缀中最新轮次的合格成功调用/结果对。继承历史、早先轮次、孤立结果、流式分块与重复调用不能证明当前证据。观察到的配对仍未经过语义验证：父级必须检查引用事件与结论。

前台结果和一次性作业在缺少所需证据时拒绝接受结果，同时保留部分输出。可继续执行的报告与结算通知携带宿主生成的证据状态。策略保存在版本 3 描述符中；普通子 agent 保留版本 2。恢复会还原策略，但要求新激活中的证据。模型参数不能替换宿主配置。

证据策略与工具过滤器组合时，进程内子 agent 获得单调执行守卫，覆盖子作用域添加和嵌套调用。Leon 专用的 `subagent_audit` 公开 `read`、`grep`、`glob`，要求 `read` 或 `grep` 证据，并将每个工具在每个会话中的初始调用限制为两次。它使用原生工具和普通最终回答；过滤器也排除 `report`、结构化输出与代码模式执行。通用委派仍可用于实现任务。协调者收到选择审计工具的指令；这不是强制所有语义审计请求走此路径的分类器。

这部分扩展了[限额委派尝试](../feature/2026-09-20-bounded-delegation-attempts.zh.md)，其基于事件的预算仍为权威来源。它不替代完成审查、产物验证或其接受标准。

自动压缩在适配器派发前安装请求准入。LLM 服务提供有效选项与绑定到已准备适配器的元数据，避免使用后来替换的注册项容量。准入遵循规范作用域链：宿主监听器全局生效，agent/预设监听器仅作用于该作用域及其后代。循环通过调用 agent 的上下文准备和派发，以保留该身份。估计输入、工具 schema 与输出预留必须适合已知窗口。拒绝保留历史和强制指令；不会裁剪它们或增加限制。策略保留在 `compaction-basic`，不进入 agent 循环。

## 考虑过的替代方案

**仅靠提示词要求只读和证据：** 不能阻止写入或虚构检查。宿主执行策略与事件关联提供可强制执行的边界。

**所有子 agent 都必须使用工具：** 简单对话与通用实现具有不同约定。证据准入为可选，并使用单独审计实例。

**增加上下文或静默换路重试：** 会掩盖过量输入，并可能改变成本或授权。对超出已知容量的请求予以拒绝，不改变路由或预算。

**把工具使用当作批准：** 成功读取不能证明结论正确。观察与语义验证保持分开。

## 影响

这些控制改善失败分类，不添加模型、自动记忆或第二个任务数据库。初始调用预算不覆盖其他委派工具或后续消息。合格工具与宿主插件是可信实现，不是操作系统沙箱。

准入是估计，不是提供方 tokenizer 的精确证明。未知模型容量仍由适配器负责。无密钥测试使用真实 Loader、循环、工具与持久化，以及脚本适配器；它们不能证明真实模型能力。源码验证不会激活运行中的宿主。Leon 工程技能现在明确指出 lint/typecheck 脚本可能生成构建，要求隔离或受控激活，而不是重建运行中的宿主。
