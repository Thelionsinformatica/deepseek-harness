# Agent Note: 强制审核器能力与已审产物新鲜度

Status: implemented

[English](2026-09-21-completion-audit-boundaries.md) | 中文

## 问题

变更工具拒绝列表仍让完成审核器调用任意 shell 和子级自有工具。subagent 启动后再安装保护已太晚：首次请求可能已在运行。同轮复用检查父会话事件，却可能批准在事件之外已被修改的文件。

## 决策

一次性 subagent 请求接受仅宿主可用的 `setup(childCtx)` 回调。提供方必须明确声明支持；不支持时在启动前失败。进程内 spawn 和 fork 在组合及结构化输出安装后、发布及推理前等待 setup。失败会回滚子级。该回调既不可由模型选择，也不会为可继续子级持久化或回放。

完成审核在尚未发布的子级作用域中安装单调执行守卫。确切的宿主创建 agent（智能体）只能调用证据读取器、产物读取器、结构化输出及部署明确配置的 `completionAuditorTools` 允许列表。默认不含通用执行工具。单独的继承过滤器不覆盖子级自有工具；执行守卫也覆盖这些工具与嵌套分发。宿主插件和获准验证器的实现仍是受信任代码。

`completion_artifact_read` 通过 `ctx.fs` 交付受限的完整 UTF-8 文件，并限定在指定工作区。只有未改变的成功最终工具结果进入 manifest（元数据清单）。新回执保存路径／提供方身份、SHA-256、字节数及明确的文件覆盖，而非文件内容。审查结束后及复用前的复检会拒绝变化、缺失文件或被重定向的目标。异步验证期间父历史必须保持不变。旧回执仍可读取，但不能复用。

为兼容非文件目标，强制产物读取需显式启用。空覆盖明确标为 `no-files-reviewed`，不得描述为文件验证。默认限制为 64 个路径，每文件 1048576 字节。常见凭据名称和所有 Windows 流语法都会被拒绝，包括附加在普通文件名上的流。所有提供方都拒绝路径开头盘符之外的冒号；普通盘符路径和 UNC 路径仍受包含检查约束。这不是通用秘密检测。读取器内容仍遵循已配置的审核器模型路由。

本决策部分取代[目标工具](../feature/2026-07-19-model-facing-goal-tools.zh.md)的 shell 策略选择和[分页审核](2026-09-20-completion-incomplete-evidence-gate.zh.md)的外部写入限制。两个记录仍保留为活跃文档，因为权限、顺序和证据交付决策仍然适用。不归档或移除历史记录。

## 考虑过的替代方案

**提示词禁令或继承拒绝列表：** 两者都不能封闭未知能力或子级自有注册。宿主在执行时强制一个封闭集合。

**在启动事件上安装：** 发布和首次推理可能早于该事件。setup 钩子提供更早的生命周期边界，而无需更改 agent loop（智能体循环）。

**对文本提及的路径计算哈希：** 提及既不能证明完整交付，也不能证明实际字节。专用读取器通过现有文件系统提供方记录最终交付结果。

**仅过滤流所属文件的基本名称：** Windows 流可以在普通文件名下保存独立字节。拒绝流语法可防止这些字节绕过凭据名称检查；这也会排除其他提供方中普通的含冒号名称。

**锁定整个工作区：** 这需要跨进程及文件系统提供方的写入准入。本次改动仅进行有界的新鲜度观察，不声称原子地排除外部写入者。

## 后果

审核器需要功能受限且获宿主批准的验证器来执行检查，不能静默继承通用 shell。能力被拒绝可能合理地阻止批准。读取至少一个文件不证明完整需求覆盖或语义正确性。哈希只是时间点观察，不是全局写入屏障，无法发现最后检查后的后续写入。

包中包含生成的 `audit-artifacts-*.js` 共享分片及现有回执分片族。工作区打包约束追踪此依赖闭包；仅通过源码类型检查不能证明已安装的包可以加载其不变量及工具入口。

专项测试覆盖 setup 顺序、回滚、取消、嵌套／自有工具绕过尝试、无效提供方身份、产物边界、交付变化、持久校验及陈旧字节。Windows Loader 测试使用真实备用流验证拒绝行为，并保留普通文件读取；提供方测试覆盖盘符和 UNC 写法。无密钥 `goal-auditor-boundaries` ACP 快照通过真实循环和持久化测试受限调用以及外部文件变化后的拒绝。这些确定性测试不证明真实模型的审核能力、付费提供方行为或生产部署。
