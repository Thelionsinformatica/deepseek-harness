# Agent Note: 文档接纳验证与证据流程

Status: implemented

[English](2026-09-22-document-admission-journey.md) | 中文

## Problem

非图像上传即使不包含图像也会访问图像存储。宽松的 base64 解码会接受格式错误的输入，验证与写入交错执行，导致后续文件被拒绝时留下此前的文件。相邻提示词文本在视觉上与上传路径连在一起。

## Decision

宿主在提交请求中的任何附件之前，验证每个非图像文件的规范 base64 和既有的单文件大小限制。仅文件输入不访问图像存储，路径指针之间使用段落分隔符。验证失败返回附件专用诊断，不包含文档内容或本地路径。文件在工具读取之前保留在本地；上传本身不表示 agent（智能体）已经读取或理解文档。

## Alternatives considered

**仅在客户端验证**无法保护直接 RPC 调用方，也无法防止宿主部分写入。

**新增文档记忆子系统**会重复现有文件工具与持久会话历史的职责。验收场景改为联合执行随产品交付的 skill（技能）目录、loader、读取工具、浏览器和会话持久化。

## Consequences

格式错误的请求既不产生上传文件，也不将提示词放入队列。这不会使文件系统提交具备事务性：验证后的 I/O 故障可能留下此前的上传文件。模型可见的路径指针增加段落分隔符，但不包含文档正文。现有图像策略、模型、权限和记忆保持不变。

## Verification

附件单元回归覆盖后续成员格式错误、不依赖图像存储的纯文件操作、字节保留与路径限制。完整浏览器文档流程上传合成 Markdown，加载已发现的 skill，通过真实工具读取已存储文件，重读持久事件，并在重新加载页面后继续对话，无需再次读取或重复目录。仅推理使用脚本替代；这些检查不衡量真实模型的推理能力，不证明进程重启恢复，也不认证生产环境的团队。
