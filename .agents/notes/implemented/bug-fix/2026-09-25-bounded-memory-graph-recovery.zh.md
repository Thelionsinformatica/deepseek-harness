# Agent Note: 有界记忆图恢复

Status: implemented

[English](2026-09-25-bounded-memory-graph-recovery.md) | 中文

## 问题

本地嵌入端点的短暂故障可能让记忆图一直失败，直到再次提交或重启。超过端点物理限制的批次或文档会导致整个分区失败，并把原有覆盖范围替换为空的失败结果。仅增加服务上下文并不足够，因为文档长度与聚合批次大小是不同的约束。

## 决策

`MemoryGraphScheduler` 仅重试瞬时传输、超时和选定的 HTTP 故障，使用每代有限尝试预算与封顶的指数延迟。启动会安排持久化的失败分区。新提交取消过时工作；禁用和 dispose（资源释放）在关闭 domain 前取消重试与推理。读取不会触发重试或重置预算。这替代了[派生图决策](../feature/2026-09-21-derived-memory-graph.zh.md) 中失败后等待提交的原有行为，同时保留其原子发布与只读边界。

图算法版本 2 将完整文本拆为有界且 Unicode 安全的分段与批次。明确的输入溢出先拆批次，再递归拆分单个分段。深度限制和整个过程的期限限制自适应操作。按长度加权的均值包含每个分段；不会修改或截断事实及修订。检索与图向量在同一有界 LRU 内按用途区分缓存，因此调用顺序不会改变图算法。

重建失败保留上一快照的准确修订覆盖范围与来源，并明确标记为失败。不完整的嵌入过程不会作为当前覆盖范围发布。workspace 与个人提供方共享这些规则；无需新增公开快照字段。配置默认值记录在提供方 README 中。

## 考虑过的替代方案

**无限重试或由读取触发重试。** 这会让读取产生推理工作，并可能在端点不可用时不断循环。有界的每代预算使成本可预测。

**截断事实或静默跳过被拒绝的文档。** 两者都会掩盖覆盖损失。完整分段保留源文本；耗尽边界后保持显式失败，而非产生虚假的成功分区。

**只扩大嵌入服务器上下文。** 这无法区分单个输入限制与聚合批次限制，并将记忆正确性绑定到某个部署的物理预算。

**将整篇文档缓存复用于分段均值。** 这使图输出取决于是否先执行检索。按用途区分的条目保持算法身份，又不增加总缓存预算。

## 后果

短暂故障可以在没有新用户写入时恢复，包括冷启动之后。重试耗尽后有意停止，直到出现新一代、重新启用或重启。长文档会增加请求数；自适应拆分与重试始终有界。即使图计算失败，已存事实仍然完整且可独立读取。

分段平均是近似算法，可能改变相似度分数；长文档召回率与阈值仍需针对模型校准。关系仍然表示相似，而非核验、因果或修改事实的授权。此变更不改变本地嵌入服务器的 2,048-token 部署预算，也不改变查询时的词法回退。

聚焦测试覆盖有限尝试、取消、资源释放、经真实 Loader 与 JSON 后端的冷启动恢复、完整输入覆盖、显式耗尽以及数值加权。可运行的 `examples/headless-agent/memory-graph-recovery.cordis.yml` 组合使用合成回环端点和临时存储，不涉及云端或生产记忆。
