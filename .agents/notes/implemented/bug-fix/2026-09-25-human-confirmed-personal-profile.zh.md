# Agent Note: 人工确认个人记忆与画像选择

Status: implemented

[English](2026-09-25-human-confirmed-personal-profile.md) | 中文

## 问题

个人记忆写入工具依据模型决定赋予显式验证和置信度 1。其 core 参数还允许该决定进入独立于查询的画像。尽管已有带确认的 Host 纠正操作，个人面板既不能选择核心成员资格，也不能重新确认未修改的文本。

## 决策

模型写入工具创建没有 validation、confidence 或 core 选择的待确认记录。模型纠正不能选择核心成员资格；正文变化会使先前确认失效。显式搜索以 `confirmationRequired` 标记待确认结果，而自动查询和核心投影要求确认。待确认记录仍可在同一所有者隔离存储中检查，不引入另一个队列，也不迁移已有数据。

Host 纠正请求增加可选 `core`；省略时保留选择。浏览器提供重新确认和明确加入/移出操作，展示完整文本供确认，并提交精确 revision。完整管理权限、启用个人记忆、所属 Session、敏感内容拒绝和审计准入仍是必要条件。成功操作追加修订及不含正文、带可选 `desiredCore` 的审计；过期 revision 失败。这些操作不是模型工具，也不增加自然语言同意解析器。

[核心画像生命周期](../feature/2026-09-22-always-present-core-profile.zh.md)仍拥有投影预算、替换、失效和回放。本决策改变批准权限，不改变该生命周期。

## 备选方案

**相信工具提示词可以识别同意。** 否决，因为模型解释不能证明对精确保留修订或画像选择的批准。

**把提案复制到第二套候选存储。** 否决，因为既有未确认记录已支持检查、纠正、精确修订及历史保留。第二套存储需要新的晋升和身份机制。

**自动降级已有已确认记录。** 否决，因为这会在没有逐条审查时修改用户数据，也无法恢复独立的历史同意证据。

## 后果

自动回忆不能在人工确认前使用新提案事实。这增加了有意的审查步骤，待确认事实被审查前可能降低召回。已有确认元数据仍有资格；它不是历史人工同意的证明，需要另行由用户指示审查。即使正文未变，确认或改变画像选择也会创建新修订。把事实移出画像不等于遗忘，也不会阻止相关的已确认查询回忆。

## 测试

聚焦的集成、运行时、Loader 和浏览器组件测试覆盖待确认准入、false 确认、过期修订、同文确认、画像选择、只读/禁用/遮蔽控制、审计选择和时间历史。无需密钥的真实 Loader 组合 `examples/headless-agent/personal-core-profile.cordis.snapshot.yml` 使用合成记录和脚本化模型响应，捕获模型可见的写入 schema、待确认工具调用、Host 确认、有界画像加入/移出及持久 JSONL 回放。这些测试不调用付费 API、不修改真实记忆，也不证明真实模型质量。
