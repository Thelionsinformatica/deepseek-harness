# Agent Note: Session archive and permanent lifecycle controls

Status: implemented

English | [中文](2026-07-31-session-archive-global-set.zh.md)

## Problem

The session row menu in the sidebar workspace browser originally carried a purely visual "Delete session" placeholder. Hiding a conversation is not the same operation as destroying its history: archive must retain the canonical log and workspace position, while permanent deletion must coordinate a possibly live Agent, append serialization, derived records, workspace accounting, and every connected client without allowing a late write to resurrect the identity or publishing success before durable work completes. The archive record also needs a registry-global home because an Ungrouped session belongs to no workspace entity. User workspace files, personal memory, and content-addressed attachments have lifecycles outside an individual conversation and must not be mistaken for session-owned data.

## Decision

**Archive is a reversible registry-global visibility overlay; restore is its inverse; permanent deletion is an explicit gateway-orchestrated lifecycle that removes only Leon-owned records for one session identity and publishes removal after the complete cleanup commits.**

- Archive storage remains `workspaceDomainState.archivedSessionIds: z.array(sessionId).default([])` with domain version 2. Pre-field media parse to an empty set through the schema default. An archived session keeps its `sessionIds` workspace slot, so archiving does not change the one-owner accounting invariant and restoring reveals the session at its existing position.
- `WorkspaceRegistry.archiveSession(id)` and `unarchiveSession(id)` run through `enqueueOperation`, and its `archivedSessionIds` getter exposes the read-only set. Archive rejects an identity that is neither live nor persisted and is idempotent for an existing member; the RPC maps that miss to `session-not-found`. Unarchive is idempotent when the id is absent from the set. `workspace.archiveSession` and `workspace.unarchiveSession` return the full committed `archivedSessionIds` snapshot, `workspace.list` supplies the reconnect baseline, and `host/archived-sessions-changed` publishes the same complete snapshot after durable changes.
- The client runtime keeps `WorkspaceListState.archivedSessionIds` as a `readonly SessionId[]` in Host order because public snapshot state uses the store engine's plain-data vocabulary; derivations construct transient Sets for membership, and the array reference changes only when ordered membership changes. The list baseline, unary echoes, and changed frames replace the whole set. A newer echo or frame that arrives during `workspace.list` outranks its stale baseline. One projection rule clears a current selection that becomes archived, covering the local action, another tab, and reconnect.
- All grouping derivations filter the same archive set, so workspace groups, Ungrouped, search, and the flat list agree. The session menu exposes non-destructive **Archive** without confirmation and destructive **Delete conversation** with confirmation. A discoverable archived-conversations dialog remains available even when its count is zero, identifies each conversation's workspace, and offers Restore or confirmed permanent deletion while keeping rejected operations visible for retry.
- `SessionPersistence.delete(id)` is the canonical deletion boundary. `PersistenceCoordinator` closes admission before entering the per-session operation chain, coalesces concurrent deletes, waits for retirement and prior writes, refuses a still-live or non-disposable prepared identity, invokes the backend once, invalidates retained state, and installs an in-process tombstone. Later append, prepare, inspect, load, or create work cannot queue behind deletion and recreate the artifact. JSONL proves the physical target and parent remain under the configured root, refuses symlink/junction targets, validates only the bounded header (so corrupt historical bodies remain deletable), removes crash-left POSIX staging hard links only when device/inode identity matches, unlinks only the exact canonical log, and fsyncs the parent directory on POSIX; every containing directory remains intact. SQLite removes the session row and its foreign-key-cascaded events in one transaction.
- `workspace.deleteSession` owns the cross-package lifecycle in the Host gateway. Its deletion fence is installed before asynchronous existence discovery and covers public create through Workspace attachment, fork through child attachment, prompts and queue mutations, archive/restore/reorder, preset switches, ordinary cold resumes, Typert lookups, and pending user questions or approvals. In-flight create, fork, resolver, and preset operations are awaited, recheck the fence after asynchronous boundaries, and cannot publish a late success or reinsert Workspace accounting. Pending questions and approvals are cancelled before teardown can await. A gateway-owned live Agent is cancelled, awaited through `whenIdle()`, and disposed through the exact handle captured when that Agent was created, forked, or resumed. Ordinary `host/session-removed` emission is suppressed during successful teardown; if deletion later fails after real detachment, that truthful non-permanent frame is emitted so clients do not retain a phantom Agent. A live Agent owned by configuration or another component is rejected with `agent-busy` because the gateway has no authority to detach it.
- After the canonical log deletion commits, the gateway idempotently purges the session projection cache, session-query persisted/live index rows, and message-feedback row. `WorkspaceRegistry.deleteSession(id)` then removes the id from every workspace record, the global archive set, and registry indexes through a durable `delete-session` pending marker; startup completes an interrupted registry cleanup instead of guessing from table shape. Only after these owners reach their absent postcondition does the gateway emit `host/session-deleted`; the unary response and Host frame remove the session from client stores without allowing the earlier disposal frame to present a permanent deletion prematurely.
- Permanent deletion owns neither the session `cwd` nor any file below it. Personal memory remains in its separate owner and lifecycle. Immutable attachment objects are content-addressed and may be referenced by more than one session, so deletion removes the conversation's references with its log but does not erase shared attachment objects or request-image cache artifacts. Reference-aware garbage collection, if added, must prove that no remaining owner references an object before reclaiming it.

## Alternatives considered

**Treat the original Delete row as archive and provide no archived manager.** Rejected as the complete product contract: archive remains the safe default, but a hidden conversation needs a discoverable restore path and users need an explicit, confirmed way to destroy session history.

**Per-workspace `archivedSessionIds`.** Rejected because Ungrouped sessions have no workspace entity to own the record.

**An archived flag on `SessionSummary`.** Rejected because it joins a workspace-domain fact into the sessions-domain projection, whose summaries still need a separate incremental notification; the cross-domain coupling costs more than the saved field.

**Host-side filtering in `workspaceView` or the `sessionIds` getter.** Rejected because archive does not change accounting, and restore needs the client to retain the full workspace position.

**Incremental archive frames.** Rejected because the set is small and changes rarely; full snapshots avoid client merge and deduplication state and match the workspace-changed posture.

**Delete the log directly from the UI or `WorkspaceRegistry`.** Rejected because neither owner can quiesce a live Agent, close persistence admission, purge optional sidecars, or order multi-client publication. The gateway already owns the Agent handles and the RPC transaction boundary.

**Recursively delete the session directory, workspace, memory, or attachments.** Rejected because JSONL needs to own only the exact log artifact, the workspace contains user files, personal memory is intentionally session-independent, and content-addressed attachments can be shared. Broad filesystem deletion would also cross symlink or junction boundaries without proving ownership.

**Force-detach any live Agent by session id.** Rejected because externally owned Agents have teardown obligations that the gateway cannot observe; explicit refusal preserves their ownership contract.

## Consequences

Users can hide, inspect, restore, or permanently delete conversations through one coherent lifecycle while archived logs and workspace positions remain durable until deletion. Permanent deletion is intentionally narrower than "erase everything associated with this person or project": it removes the canonical session history and Leon-owned per-session projections, indexes, feedback, archive membership, and workspace references, but preserves the project directory, user files, personal memory, and shared immutable attachments.

The canonical log commit is the irreversible point. Sidecar and registry cleanup follows it and remains retriable and idempotent; a failure after that point returns an error and withholds `host/session-deleted` until a retry completes the absent postcondition. Process-local persistence tombstones prevent resurrection during that process, while explicit recreation of the same id belongs to a new lifecycle after restart. Deployments with an additional session-derived owner must add its purge to the gateway workflow before claiming complete deletion.

This implementation assumes one Leon Host has exclusive write ownership of a JSONL persistence root. Node does not expose a portable unlink-by-handle/unlinkat primitive, so the backend performs containment plus device/inode revalidation immediately before pathname unlink but cannot eliminate a malicious local filesystem swap in the final syscall window. The gateway also has no durable cross-store deletion journal yet: a process or power loss after the canonical log commit but before all sidecars and Workspace accounting finish requires an explicit retry from the retained Workspace reference. Multi-process writers, hostile local mutation of the persistence root, and automatic crash recovery across every derived store remain deployment hardening work rather than guarantees of this local single-user lifecycle.

Contract tests cover JSONL and SQLite exact-target deletion, concurrent-operation ordering, tombstone admission, archive/restore durability, interrupted workspace cleanup, sidecar purge serialization, gateway-owned live teardown, external-owner refusal, post-commit Host framing, client echo/frame convergence, archive filtering, restore errors, and confirmed deletion. Product-visible tests keep the destructive path on disposable sessions and verify that the workspace directory survives.
