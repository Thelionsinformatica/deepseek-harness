# Agent Note: Leon 本地产品配置

Status: implemented

[English](2026-08-21-leon-local-product-profile.md) | 中文

## 问题

该 fork 的产品身份仅存在于安装后的本地补丁中。这些补丁会被重新构建覆盖，在多个界面上仍保留原产品名称，并导致运行中的应用与已审查源码不一致。葡萄牙语只通过通用回退层提供，因此客户端插件拥有的设置文案与已知权限名称仍显示为英文。部署也没有随附一等的 Leon preset。

官方品牌把一张 2398 x 603 的 PNG 嵌入 JavaScript bundle，尽管应用已经发布了紧凑的 favicon。Web 文档声明为英文并使用 fullscreen PWA，这与本地化的桌面式体验不一致。生产依赖图还在已有兼容修复版本的传递包中包含已知安全通告。

## 决策

Leon 在该 fork 中成为由源码拥有的产品配置。CLI（命令行界面）在既有 preset 旁随附 `leon` preset，提供葡萄牙语元数据、Leon 人设，并把 Ralph 工作流限制为最多 12 Round。浏览器以巴西葡萄牙语本地化高频设置、插件清单、preset 与权限界面。已知权限标识符在其展示边界翻译；自定义权限名称保持不变。

该 preset 随附 `leon-project-engineer` skill，并相对 preset 自身解析其目录。只有使用 Leon 的 agent 会在用户和项目 skill 之外获得该目录项。该 skill 区分解释、诊断、实现与对外发布；它指导项目检查、范围受限的编辑、与风险成比例的验证、diff 复核、进度报告和基于证据的交付，但不授予额外工具或权限。

preset 设置页把部署默认值提升到始终可见的「主要助手」分组，并将其余随附 preset 放入初始收起的「高级模式」分组。Leon 描述会说明项目工程与可选持久记忆，但不暗示默认禁用的 Letta 集成始终处于启用状态。卡片的次要操作在图标旁带有可见文本标签。

官方品牌渲染已经公开的 `/favicon.ico`，不再把大型光栅资源导入客户端 bundle。较小的公司标签保持可读，在强制颜色模式下亦然。Web 文档声明 `pt-BR`，manifest（元数据清单）使用 `standalone` 显示模式，并采用与深色应用外壳一致的颜色。

安全修复对受影响的传递包使用限定版本范围的工作区 overrides，以选择兼容的修复版本。这样既保留既有包 API 边界，也移除了审计发现的生产安全通告。lockfile 记录最终解析版本。

PR（Pull Request）CI 在 upstream 仓库中保留原项目的私有企业 runner，并在 fork 中选择标准 GitHub 托管的 Linux 与 Windows runner。这样在 fork 启用 Actions 后，继承的工作流便可执行，同时不会削弱 upstream 的容量或 failover 策略。

构建后的 fork 是运行时真源。本地启动代码可以选择数据目录，并使用操作系统访问控制保护该目录，但不会修改已安装依赖或重写提供方凭据。提供方配置仍是用户拥有的运行时状态。

## 测试

交付的 Web 组合测试会挂载 Leon，确认该 skill 未进入全局层，并通过真实 skill 工具加载其完整指令。一份无密钥 Loader 快照固定模型可见的目录摘要、随附源元数据、资源目录和已加载内容。

agent-preset 客户端测试组会固定主要／高级分组、折叠区的无障碍状态、Leon 本地化描述与带标签的操作。无密钥 Web 创作路径通过真实设置页捕获初始收起的名单，并在测试随附 preset 操作前展开「高级模式」。

## 考虑过的替代方案

**每次安装后继续修改 `node_modules`。** 否决，因为该结果无法在 fork 中审查，会在重新安装时消失，并可能让源码、构建产物与运行时显示不同身份。

**仅通过通用葡萄牙语回退进行翻译。** 否决，因为插件拥有的文案和动态权限标签会绕过该字典。每个 owner 使用原生字典可保留实时语言切换，并让缺失覆盖变得可测试。

**立即重命名每个 `@deepseek-ai` 包。** 延后。该包族是跨 manifest、生成产物、文档与发布自动化的内部 monorepo 协议。部分重命名会破坏工作区组装；完整的公开 scope 迁移需要独立的发布决策。

**应用不限制范围的主要版本依赖 overrides。** 否决，因为这可能静默跨越 API 约定。overrides 仅限于与仓库当前消费的依赖范围兼容的修复版本。

**在 fork 中保留仅 upstream 可用的 runner 标签。** 否决，因为任务会一直等待 fork 无法访问的私有 runner 池。根据仓库选择 runner，可以在保留一份工作流约定的同时，为 fork 提供可用的执行路径。

**把项目工作流放入 Leon 人设。** 否决，因为每次请求都会承担提示词成本，而与软件项目无关的对话也会收到工程指令。可发现的 skill 使目录项保持简短，并且只对匹配工作加载工作流。

**把 Codex 产品内部实现复制到 fork。** 否决，因为可迁移的行为是项目工作流，而产品专属内部实现会建立不受支持的依赖关系，也不符合 harness 的 skill 接口。

## 结果

干净的官方构建现在无需安装后修改即可生成 Leon 身份与巴西葡萄牙语界面。同一个 preset 可用于新安装，而具有相同 id 的既有本地 preset 仍可按 roster 的正常根目录优先级选择。

Leon 会话会自动发现随附的项目工作流，且不影响其他 preset。模型在这些会话中会看到一条额外的目录摘要，只有在任务匹配该 skill 或用户调用它后才会承担完整指令的 token 成本。

Leon 为部署默认值时，设置中初始只展开它这一张随附 preset 卡片。其他内置模式仍可按需使用，却不会与主要助手争夺注意力；无需悬停也能理解其操作。

本次增量只有使用频率最高的命名空间采用原生葡萄牙语。既有回退字典继续覆盖尚未迁移的字符串，因此后续包可以独立迁移到 owner 本地字典。

官方品牌 bundle 不再包含大型内联 PNG，安装后的 PWA 以独立应用方式运行。在本次决策点，生产依赖审计结果为干净；未来 lockfile 更新必须重新执行审计，而不能假定 overrides 始终足够。

本地提供方凭据既不会复制到仓库，也不会被构建或启动器更改。运维访问控制设置仍取决于平台；如果无法保护选定的数据目录，必须明确失败。

fork owner 仍需在仓库设置中启用一次 GitHub Actions；runner 选择无法绕过 GitHub 的这项安全控制。
