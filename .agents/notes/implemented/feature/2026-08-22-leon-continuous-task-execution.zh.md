# Agent Note: Leon 连续任务执行

Status: implemented

[English](2026-08-22-leon-continuous-task-execution.md) | 中文

## Problem

Leon 可以接收一项复杂实现请求、发布任务列表，却仍在一个很短的轮次后停止，因为继续执行此前依赖模型主动调用 `create_goal`。任务面板随后会保留一项进行中内容，但无法区分活跃执行与空闲 agent。这会造成两种错误印象：可见任务保证工作会继续，以及带动画的待处理条目证明工作仍在运行。

## Decision

Leon 预设在 `goal-round-driver` 中显式启用确定性的自动 goal 准入。下游提示词策略接纳人类直接发送给根 agent 的消息后，若实现请求包含无歧义的执行动词，并且还有具体工作目标、持续执行语言或足够复杂的结构，同时不存在尚未结束的 goal，就会创建一个上限为十二个 Round 的持久 goal。`teste`/`test` 这类有歧义的名词本身不算执行指令；明确的禁止编辑或禁止使用工具的分析探测保持单轮。短的 `responda apenas`/`answer only` 探测也保持单轮；如果该短语出现在其他可执行的实现请求后部，则不会抑制工作。其他预设不受影响。

自动 Goal Round 会保留同一份 `todo_write` 投影。在每个续行边界，其提示词要求模型在写入前用已检查的工作区产物以及最近失败或缺失的验证来核对该计划，保留已有条目，并从首个未完成条目继续，而不是重新创建先前工作。命令证据只能来自实际工具结果，且最终变更后必须再次执行所要求的运行时检查。Leon 还会为 `todo_write` 配置 `preserveExistingItems: true`：后续写入可插入新发现的工作并更新状态，但不能删除、重命名、重排或重新打开已有的已完成条目。之后的人类直接消息会清空上一份计划，因为它开始一项新的人类任务。Leon 的 `tool-goal` 组合启用 `completionRequiresCompletedTodos`，并把全新的 `spawn` 完成审核器路由到 Google Gemini。因此，完成变更既要求非空任务列表全部完成，也要求独立结构化 PASS 且没有发现项；拒绝会把修正要求返回给活跃 Goal Round，绝不会发布终态。

Goal Round 指令会把本地服务器视为受管理的后台任务。一个后台调用只包含服务器启动命令，HTTP 健康检查在单独的前台调用中运行，模型随后只停止返回的任务句柄。这可以防止长时间运行的服务器阻塞同一 shell 命令中位于其后的健康检查。Leon 预设通过 `enforceManagedServerValidation: true` 对已识别服务器命令强制执行该顺序，并会在 shell 解析前拒绝前台服务器启动、嵌套 PowerShell 任务以及服务器与健康检查组合调用。健康检查失败或连接被拒绝时，必须先读取返回的服务器任务输出再更换端口，使服务器 stderr 成为主要运行时证据。端口被占用时改用其他端口或报告冲突，绝不能因此终止现有所有者。在 Windows 上，Leon 预设还会为 `tool-pwsh` 配置 `allowHostProcessTermination: false`，因此常见的直接终止进程与服务形式会在 shell 解析前失败。这些语法策略只提供纵深防御；Windows sandbox 与审批策略仍是主机访问的权威机制。

Web 任务面板会组合权威 todo 投影与会话 running 位。列表未完成时，只有 agent 正在运行才显示 `Leon 正在工作`，空闲时显示 `Leon 已停止 — 任务未完成`；全部完成的列表显示 `工作已完成`。空白自动会话会在显示模型状态前预置快速本地路由，而提示词准入可以把活跃轮次切换到主要本地层级。选择器会继续显示实际当前路由和推理强度。

## Alternatives considered

**依赖模型调用 `create_goal`。** 已否决，因为正在修复的失败正是较小本地模型可能在工作明显包含多个步骤时仍省略该调用。

**把每条用户消息都视为持久 goal。** 已否决，因为问题、短回复和健康探测应在一个轮次内结束，不得消耗自动 Round 预算。

**只要有条目处于进行中就保持任务动画。** 已否决，因为 todo 状态是模型编写的计划状态，而不是 agent 进程正在运行的证据。

**允许在没有任务列表时完成。** Leon 预设否决此方案，因为它会保留此前的虚假成功路径。其他组合只有显式配置后才启用该门禁，因此继续保持向后兼容。

**端口占用只依赖提示词指引。** 已否决，因为较小本地模型在看到冲突后仍可能发出终止命令。Leon 执行器会在任何进程启动前拒绝常见的直接形式。

**在所有预设中禁用直接进程控制。** 已否决，因为通用组合可能有意管理主机进程。默认值继续允许，Leon 则显式启用更严格策略。

## Consequences

复杂的 Leon 实现工作会在同一会话中继续，无需用户输入「继续」，直到达到配置上限或进入具体终态。这些内部 Round 会保留可见计划，并通过运行中的完成工具卡片如实区分工作中、已停止但未完成、验证中和已完成状态。状态核对可减少长轮次或压缩后的重复工作，最终变更后的运行时证据与全新 Gemini 审核器可减少执行器自身假设造成的虚假完成。三调用服务器协议可避免前台挂起，并防止常见的端口冲突恢复流程把无关 Windows 服务作为目标。审核器仍属于模型判断，而非密码学完成证书。
