# Agent Note: 本地影子记忆候选项提取

Status: implemented

[English](2026-08-22-shadow-memory-candidate-extraction.md) | 中文

## 问题

显式记忆工具保留了用户控制，但无法提供证据来判断 Leon 可以安全建议哪些对话事实供以后保留。通过 LLM 提取每一轮，或立即写入推断事实，会在人工审查路径存在之前引入成本、不确定性和隐私风险。

## 决策

- `shadowExtraction` 是 `@deepseek-ai/dsh-tool-memory` 上的选择加入模式，并要求稳定的 `shadowOwnerId`。Leon preset 为其单用户本地部署启用该模式；多用户部署必须提供自己的所有者边界，否则应保持禁用。
- 只检查第一个已接受步骤中最新一条由人类编写的消息。保守的确定性模式识别显式记忆请求，以及稳定的偏好、决定和配置陈述。普通问题与后续工具循环步骤不会创建候选项。
- 每个安全候选项只存储在本地 `memory_candidate.candidates` 审查队列中，并带有 workspace、会话、所有者、类别、置信度、重要性与敏感度元数据。运行时 `memory/candidate` 事件只包含元数据，绝不包含候选文本。
- 类似凭据的候选项会被标记为阻止，其文本在持久化前被省略。其他敏感主题会被标记为需要确认。
- 只基于元数据的确定性策略会给出一个带版本的建议：被阻止的凭据为 `block`，需要审查的敏感内容为 `confirm`，证据较弱的候选项为 `reject`，显式且高置信度的非事实候选项为 `store`，其他安全候选项保持 `shadow`。记录与事件会写入相同的决策和原因。
- `store` 表示可以交由操作员批准，而不是自动持久化。即使是高置信度偏好，也只保留在审查队列中。
- 影子提取绝不会调用 `ctx.memory.create()`，不会注入模型上下文，也不会公开工具结果。在后续经审查的策略授权其他路径之前，持久记忆仍只能通过 `memory_remember` 显式更改。

## 验证

单元覆盖固定了 PT-BR 显式提取、稳定决定提取、普通问题拒绝、分类、凭据省略以及全部五种确定性策略结果。真实 agent loop 集成证明安全文本只进入本地影子队列，所有者和 workspace 元数据存在，运行时事件不含文本，存储中没有凭据文本，并且 `ctx.memory` 保持不变。它还证明显式的高置信度偏好会得到 `store` 建议，而持久记忆仍为空。真实 Loader 组合会启动同一条 Cordis 配置路径，并固定候选项持久化而不写入记忆。

## 考虑过的替代方案

**使用 LLM 提取每一轮。**予以拒绝，因为这会通过模型发送更多对话内容、增加提供方成本，并让首批审查数据变得不确定。

**把高置信度候选项直接写入持久记忆。**予以拒绝，因为置信度不等于用户授权，而且操作员审查界面尚未交付。

**只保留现有回忆遥测。**予以拒绝，因为检索计数无法显示提取器会提出哪条新的稳定事实，因此不能支持有意义的人工比较。

## 后果

Leon 现在可以生成本地、可审查的数据集，用于调整记忆策略，而不会静默学习或增加模型 token 用量。初始提取器会有意漏掉改写表达和复杂隐含事实；在此阶段，改善回忆不如避免错误保留重要。影子记录会在本地存储后端保存安全候选文本，因此备份和未来审查控制必须维持相同的本地访问边界。
