# Agent Note: 确定性最终记忆排序

Status: implemented

[English](2026-08-25-deterministic-final-memory-ranking.md) | 中文

## Problem

词法提供方与可选语义提供方可能使用不同分数范围，返回重复或无效命中，也可能缺少用于区分近期已审查决定与旧的未确认事实的持久信号。把提供方顺序直接交给显式搜索与自动回忆，会使模型或检索提供方的更换产生不一致上下文。

## Decision

`dsh-tool-memory` 拥有一个由 `memory_search` 与自动回忆共享、独立于提供方的最终排序阶段。每项操作最多获取请求结果数的三倍候选，并把提供方命中上限设为 50；随后拒绝非有限分数、跨 workspace 记录、空内容、无效 revision 或时间戳、无效可选元数据和未知确认类别。重复 id 先保留最高 revision，再比较提供方分数，最后比较更新时间。

最终分数在候选集合内规范化非负提供方相关性，并赋予 55% 权重。以可配置的 30 天半衰期计算的指数新近程度占 20%，规范化 importance 占 15%，确认类别与来源 confidence 的乘积占 10%。已审查记忆的确认分数为 1，显式记忆为 0.9，旧记忆的 importance 与确认值使用中性的 0.5。相同结果依次按最终分数、更新时间和 id 稳定决胜。

提供方中立的记忆 API 接受可选的零到一 `importance`、`confidence`，以及 `explicit` 或 `reviewed` 确认类别。本地提供方无需持久 schema 迁移即可保存这些字段，因为所有字段均为可选且旧记录继续有效。显式工具写入带有完整 confidence 与 `explicit` 确认；经批准的自动写入保留提取出的 importance 和 confidence，并使用 `reviewed` 确认。

Leon preset 明确固定这些权重。设置 `ranking.enabled: false` 后，验证、workspace 过滤、去重、敏感信息过滤、结果限制和上下文限制继续有效，但保留的命中按提供方分数排序。关闭本地语义检索属于独立操作，不会删除排序元数据。

## Verification

聚焦测试覆盖分数组成、旧记录默认值、确定性相同分数处理、重复 revision 与分数、无效和跨 workspace 提供方输出、结果上限、提供方分数回滚、无效配置、持久元数据、有界额外候选获取和自动回忆字符预算。8 个记忆测试文件共通过 112 个运行时用例，已更改的记忆包与 Leon CLI 也能共同编译。

## Alternatives considered

**直接使用提供方顺序。** 拒绝作为默认行为，因为词法与语义分数没有稳定的共同含义，也无法纳入持久确认或 importance。该方式保留为配置回滚路径。

**让对话模型重新排序。** 拒绝，因为它会增加 API 成本与延迟，向所选模型暴露更多记忆文本，并让顺序依赖处理当前轮次的本地或远程模型。

**持久保存某个提供方专用的最终分数。** 拒绝，因为相关性取决于查询，而且这种方式会把持久记忆耦合到一个 embedding 模型或词法实现。

## Consequences

更换对话模型或检索提供方时，Leon 仍会获得稳定且有界的记忆上下文；已审查和近期事实可以排在较弱的旧匹配之前。最终分数有意保持为启发式规则：LEON-EVAL-PTBR 必须使用有代表性的葡萄牙语任务校准权重。时间状态、过期和替代关系属于独立过滤工作；本排序不会根据年龄推断这些信息。
