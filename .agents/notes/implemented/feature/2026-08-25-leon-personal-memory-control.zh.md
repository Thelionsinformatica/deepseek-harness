# Agent Note：Leon 个人记忆用户控制

状态：已实现

[English](2026-08-25-leon-personal-memory-control.md) | 中文

## 问题

Leon 已有持久个人记忆服务和模型工具，但用户无法在浏览器中独立检查已存内容、纠正过时偏好、永久删除记录，或停止自动个人回忆。复用 workspace 管理会掩盖不同的所有权边界，并可能把个人事实呈现为项目数据。

## 决策

当部署配置 `personalOwnerId`，并组合 `personalMemory` 与 `settings` 时，现有 Host 拥有的 `memoryCandidateReview` Remote 会公开一组独立的个人记忆管理操作。浏览器绝不会接收或选择所有者 id。Session 用于授权本地请求并提供来源，但其 workspace 不会派生或改变个人所有权。

`personal-memory` settings namespace 存储实时 `enabled` 偏好。禁用后，会在提供方执行前阻止个人回忆、创建与纠正。列表与永久遗忘仍然可用，因此即使回忆关闭，用户仍可检查或删除现有记录。重新启用会立即应用到共享 runtime，并通过现有 settings 提供方在重启后保持。

Web UI 在建议与 workspace 记忆旁新增第三个 `个人` 标签页。它支持有界列表与搜索、显式添加、精确 revision 纠正、永久遗忘和启用控制。每次变更都有可见确认。类似凭据的内容会同时在 Host 管理边界与提供方中立个人记忆边界被拒绝。

个人管理会把不含内容的意图与结果记录写入 `personal_memory_admin`；该域与 workspace `memory_admin` 以及个人记录本身彼此分离。审计记录包含已配置所有者标签、Session、操作、id、revision、请求的启用状态、时间戳、状态和稳定失败码，但绝不包含记忆正文。

## 验证

Runtime 测试证明禁用后回忆与写入失败，而列表与遗忘仍然可用。Host 集成测试证明跨所有者隔离、显式确认、添加/纠正/遗忘行为、settings 持久化、即时启用状态变化与不含内容的审计记录。浏览器测试覆盖 Remote 结果解包以及完整葡萄牙语面板流程，包括确认、重试、禁用、纠正与删除。重新生成 Typert 约定后，Host 与 Client TypeScript aggregate 均可编译。

## 已考虑的替代方案

- **复用 workspace 记忆管理** — 拒绝，因为 Session workspace 只是授权锚点，不是个人事实的所有者。
- **禁用记忆时隐藏记录** — 拒绝，因为隐私控制不能阻止检查或删除现有数据。
- **让浏览器发送所有者 id** — 拒绝，因为这会把呈现状态变成授权决定。
- **把启用标志只存在组件状态中** — 拒绝，因为重启后会丢失，也无法治理模型工具或自动回忆。

## 后果

Leon 现在让用户直接控制跨项目的个人连续性，同时不削弱 workspace 隔离。该功能保持本地、无密钥、提供方独立、确认门控；从组合中省略 `personalOwnerId` 即可移除。

单一所有者标签是部署配置，不是经过身份验证的多用户身份。静态加密、导出/备份控制与组织范围记忆仍属于后续独立工作。
