# Agent Note: 按 workspace 隔离的记忆候选项人工审查

Status: implemented

[English](2026-08-25-memory-candidate-human-review.md) | 中文

## 问题

影子提取已经生成有用的本地候选项，但操作员无法通过 Leon 界面检查或决定这些候选项。直接公开存储表会泄露内部所有权标识符，也会让一个浏览器标签页替换另一个标签页的决定。把批准直接视为写入最终记忆的许可，还会把两道不同的安全门禁合并为一道。

## 决策

- `MemoryCandidateReviewService` 拥有规范的 `memory_candidate.candidates` 域，并公开生成的 `list` 与 `markReviewed` Remote 方法。
- 每项操作接收会话 ID，而不是 workspace ID。Host 会把活动或已持久化的会话解析到已注册的 workspace，并在返回或更改候选项之前强制执行该分区。
- 浏览器投影会省略内部 `workspaceId` 与 `userId`。Web 客户端只接收审查内容与安全决策元数据。
- 审查写入按候选项串行化。重复相同决定具有幂等性，而用冲突决定替换现有决定会失败。
- 被阻止、被策略拒绝以及没有内容的记录不能获批。
- Leon Work 会话头部包含本地审查弹窗，提供批准、拒绝、加载、空状态与重试状态。弹窗明确说明批准只记录决定。
- 审查绝不会调用 `ctx.memory.create()`，也绝不会把候选项注入模型上下文。最终持久化仍属于后续经过独立验证的阶段。

## 验证

Host 集成覆盖证明了批准与拒绝记录、时间戳与审查者身份、幂等性、冲突决定拒绝、跨 workspace 拒绝、浏览器投影脱敏以及零最终记忆写入。浏览器组件覆盖证明了按需加载、可见类别与置信度、批准与拒绝操作、不符合条件记录的批准按钮禁用、空状态，以及本地失败后的重试。Host 构建会生成发布用的 `review.js` 入口，而 Typert Client 合同只导入客户端安全的 `types` 子路径。

## 考虑过的替代方案

**直接向浏览器公开存储域。**予以拒绝，因为存储记录包含内部所有权标识符，而且浏览器不应自行选择 workspace 边界。

**使用浏览器提供的 workspace ID。**予以拒绝，因为会话是现有的用户可见授权锚点，Host 可以据此推导所有权，而不是信任调用方提供的分区。

**批准后立即写入最终记忆。**予以拒绝，因为审查与持久记忆验证是独立控制；将它们合并会让第一版界面变得不可逆。

## 后果

Leon 现在具有可见、本地且可审计的人工决策流程，同时不会静默学习。已审查候选项会作为证据保留在影子域中，目前还不会改善未来回忆。后续持久化阶段必须只消费已批准记录，重新验证内容与作用域，并保留可逆的审计轨迹。
