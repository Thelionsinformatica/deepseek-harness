# Agent Note: 安全的自动记忆上下文组合器

Status: implemented

[English](2026-08-25-safe-memory-context-composer.md) | 中文

## Problem

相关记忆仍然是源自用户的持久文本。保留值可能包含提示注入尝试、重复的提供方命中、敏感内容或属于错误 workspace 的记录。排序和提供方验证能够降低风险，但不会定义最终面向模型的序列化，也不能证明哪些记录真正符合上下文预算。

## Decision

`dsh-tool-memory` 现在会在确定性排序之后，把自动回忆交给统一的 `MemoryContextComposer`。组合器保留排序顺序，按记忆 id 去重，重新检查准确的 workspace 所有权和类似凭据的内容，清理首尾空白，并跳过无法完整放入最终字符预算的记录。它绝不会截断记忆值。

模型收到一个带来源的插件快照。固定的安全边界位于所有值之前，声明该信封是不可信数据而不是指令。JSON payload 再次声明 `trust: untrusted` 和 `instructionAuthority: none`。每个保留值只暴露记忆 id、revision、value 和来源 session；workspace id、原始路径、排序分数和时间戳都保留在模型上下文之外。

候选遥测现在统计最终组合器实际保留的记录，而不是预算处理前的全部排序命中。提供方失败、取消或最终信封为空时仍安全地不执行任何注入，正常模型轮次继续运行。

## Verification

单元测试把模拟的 `Ignore previous instructions` 值限制在不可信 JSON 信封内，验证排序顺序、去重、跨 workspace 拒绝、敏感与空值拒绝，并证明跳过超大记录后，后续精简记录仍可进入预算。组合器的语句、分支、函数和行覆盖率均为 100%。agent-loop 测试验证有效注入、512 字符最小预算、提供方失败 fallback 和 pre-step 取消。全部 53 个 `tool-memory` 测试通过。

## Alternatives considered

**插入原始记忆字符串。** 拒绝，因为保留数据与 agent 指令之间的边界会变得含糊，而且来源信息会丢失。

**为每个命中渲染分数与时间戳。** 拒绝，因为这些字段会占用最小上下文预算，却无法帮助对话模型。它们仍保留在本地记录和遥测中。

**截断超大值。** 拒绝，因为不完整事实可能产生误导，并可能切掉限定条件或安全上下文。

## Consequences

Leon 获得精简、可审计且带有明确指令权限边界的自动记忆上下文。这是结构化的提示注入防御，并不声称任意已存文本绝不可能影响模型。现在，提供方和最终排序都会执行时间过期与替代过滤，因此非活动修订无法到达这个自动上下文边界。
