# Agent Note: 时间记忆历史

Status: implemented

[English](2026-08-25-temporal-memory-history.md) | 中文

## Problem

过去纠正持久事实时会原位替换其值。比较并设置的 revision 检查能够阻止陈旧写入，但先前事实、其有效区间和执行纠正的会话将无法再用于审计。定时纠正还要求在转换时刻前后都只有一个明确的活动修订。

## Decision

记忆记录 schema V2 增加可选的 `validFrom`、`validUntil`、`expiresAt`、`supersedes` 和 `supersededBy` 元数据，同时继续读取 schema V1 记录。本地提供方把不可变的先前修订存储在与当前修订相同的谱系值中。因此，一次串行存储更新会原子提交新的当前状态及其历史。

普通搜索只解析查询时钟下处于活动状态的修订。立即纠正会在转换时刻结束先前修订；未来纠正会让先前修订持续有效到新的 `validFrom`。已过期、尚未生效、格式错误和已被替代的修订不会进入普通或自动回忆。显式 `includeHistory` 搜索通过词法路径返回经过验证的审计修订，绝不会把历史文本发送到语义索引。

随产品提供的 Leon 组合选择 `historyMode: temporal-v2`。`historyMode: v1` 是面向后续纠正的紧急回滚：它恢复原位覆盖，同时不会让已有 V2 记录变得不可读，也不会关闭活动搜索的有效期与过期过滤。

## Verification

测试覆盖矛盾纠正、多修订谱系、定时切换、过期、显式清除过期时间、旧 V1 读取与更新、格式错误的时间介质、workspace 隔离、原子写入失败、显式历史工具输出、自动仅活动回忆和 V1 回滚。9 个记忆测试文件共 128 个用例全部通过。`memory-local` 及其持久 schema 的聚焦覆盖率在语句、分支、函数和行四项均达到 100%。

## Alternatives considered

**独立历史表。** 暂缓，因为提交当前状态和历史需要跨表事务约定，而提供方中立的存储接缝目前没有暴露该约定。

**覆盖并记录可观察性事件。** 拒绝，因为日志不是持久事实来源，无法可靠重建全部已存元数据。

**通过语义回忆发送历史修订。** 拒绝，因为自动回忆必须保持仅活动状态，而且同一 id 的多个 revision 会使语义缓存身份更复杂，却不能帮助普通对话。

## Consequences

Leon 可以更换模型或重启，而不会丢失某个持久事实在特定时间有效的历史。普通响应只接收一个当前事实，显式审计则可以检查保留的纠正链。存储量会随纠正次数增长，因此保留或压缩策略仍是后续工作。
