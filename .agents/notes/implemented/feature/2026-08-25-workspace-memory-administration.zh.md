# Agent Note: Workspace 记忆管理

Status: implemented

[English](2026-08-25-workspace-memory-administration.md) | 中文

## 问题

Leon 已经可以通过面向模型的工具回忆、纠正和遗忘持久事实，影子候选项也已有人工审查队列。但操作员仍缺少一种直接方式来查看已保存事实、筛选时间历史、纠正精确 revision，或在不要求模型执行操作的情况下遗忘一条谱系。

## 决策

- 为 `ctx.memory` 添加提供方中立的 `list()` 操作，用于按 workspace、可选文本与生命周期状态返回有界管理分页。
- 保持公开的模型工具表面不变。已保存记忆管理是浏览器到 Host 的 Remote，绝不会进入模型上下文。
- 将每个请求从 Session id 解析到且仅解析到一个已注册 workspace。浏览器不能提供 workspace id 或原始路径。
- 在纠正或遗忘前要求可见的两阶段确认以及精确 id 和 revision。Host 会独立强制执行 `administrationMode: full`；`read-only` 是回滚模式。
- 在每次变更尝试前写入不含内容的审计记录，并在之后以机器结果完成该记录。审计行包含 Session、workspace、操作、记忆 id、revision 与结果，但不含记忆内容。
- 在浏览器投影前遮蔽旧记录中类似凭据的内容。包含类似凭据内容的纠正会在持久化前被拒绝。

## 验证

提供方测试覆盖生命周期筛选、分页、历史与 workspace 隔离。Host 集成测试覆盖列表、纠正、遗忘、确认、只读回滚、凭据遮蔽与审计结果。浏览器测试覆盖已保存记忆列表、全部状态筛选、可见确认、纠正、遗忘与错误路径。生成的 Host 约定与聚合客户端类型检查证明该 Remote 保持浏览器安全。

## 考虑过的替代方案

- **把管理列表公开为第五个模型工具**：拒绝，因为操作员 UI 不需要增加提示词 schema 成本，也不应授予模型更广的查看权限。
- **使用空查询复用搜索**：拒绝，因为搜索面向相关性、默认活动记录且面向模型，而管理需要确定性分页与明确的生命周期筛选。
- **只在变更后写审计**：拒绝，因为崩溃可能留下未经审计的状态变化。接纳记录在提供方调用前写入，并在之后完成。

## 后果

用户现在可以直接查看并治理 Leon 已保存的 workspace 事实，同时保留时间历史、revision 安全与 workspace 隔离。该功能不会创建全局记忆、编辑自动写入允许列表，也不会把管理数据放入提示词。只需把 `administrationMode` 切换为 `read-only` 即可禁用变更。
