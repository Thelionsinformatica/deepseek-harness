# Agent Note: Web 技术上下文可见性

Status: implemented

[English](2026-08-29-web-technical-context-visibility.md) | 中文

## Problem

transcript 会在用户消息与 assistant 消息旁渲染每条非用户提示词组装消息。系统指令、skill（技能）目录和时间上下文既是模型所需输入，也是持久审计证据，但在普通聊天中逐条显示会让提示词准备看起来像面向用户的工作，并遮挡任务进度。

## Decision

由宿主设置支撑的 `ui-conversation.showTechnicalContext` 偏好仅控制 transcript 呈现，默认值为 `false`。ChatView 在渲染和滚动计算之前，从可见顺序中移除投影来源角色为 `inject` 的上下文节点。Conversation 快照、持久会话日志、上下文 renderer、模型请求和导出会话均保持不变。

常规设置提供 `Hidden` 与 `Shown` 选项，二者和 ChatView 使用同一个响应式偏好来源。修改偏好会立即更新已打开的对话，不会创建新会话或重写历史。

来源角色为 `recall` 的上下文不受该偏好影响并始终可见，因为它向用户说明跨会话连续性的来源。其现有默认折叠展开项与生产者标签保持可用。

## Alternatives considered

**从投影或持久化中移除注入消息。** 否决，因为面向模型的上下文必须能从会话日志重建，会话导出也需要相同的审计证据。

**使用 CSS 隐藏上下文行。** 否决，因为隐藏的 DOM 节点仍会影响无障碍访问、滚动锚点和已渲染行计算。

**把被召回的会话上下文和其他注入一起隐藏。** 否决，因为召回是与用户相关的连续性证据，而不是内部提示词准备。

## Consequences

普通聊天突出用户请求、任务活动和 assistant 结果，同时保留明确的诊断显示选项。可见顺序过滤必须参与首节点、尾节点、长度、分页锚点和跟随滚动计算，使隐藏的注入不会移动读者位置。测试固定默认值、宿主持久化、实时切换、召回例外和普通消息不变。
