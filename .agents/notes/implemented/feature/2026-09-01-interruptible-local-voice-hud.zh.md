# Agent Note: 可打断的本地语音与活动 HUD

Status: implemented

[English](2026-09-01-interruptible-local-voice-hud.md) | 中文

## Problem

Leon 能够捕获和转写麦克风音频片段，但既不能朗读已完成回答，也没有一个紧凑状态来区分聆听、模型工作、工具执行、待处理人工交互和故障。因此，会话继续工作时，用户可能只看到静态 composer。引入第二个 assistant 服务器或平行事件流会重复现有 Conversation 投影，并产生相互冲突的取消和审批语义。

## Decision

`ui-voice` 客户端插件拥有一个共享捕获控制器和一个共享的可打断播放控制器。麦克风保留在 `conversation.input.right`；非交互式 HUD 占用 `conversation.composer.dock`。它的纯投影读取捕获与播放视图以及普通 `ConversationSnapshot` 的 `running`、`runningCalls`、`pending`、`partial`、`promptError` 和 `lastAgentError` 字段。它绝不会在这些来源之外制造进度。

首个播放驱动使用浏览器的操作系统语音目录，只接受 `localService === true` 的语音，优先选择 `pt-BR` 和 Microsoft Daniel，并在只有远程语音时快速失败。`VoicePlaybackDriver` 保持可替换，使未来的宿主合成器无需修改控制器或 UI 约定。

通过麦克风提交的提示词使用普通 composer 事务，但会等待其因果接纳回执。宿主返回精确的持久用户消息 id，Chat 投影再提供该消息解析出的轮次。FIFO 协调器会按提交顺序保留多个语音后续消息，即使接纳回执乱序到达也是如此。每个精确轮次中，只有最后一条已完成且未被打断的 assistant 文本可以发声。推理、工具块、围栏代码、恢复的历史记录、键入轮次和空回答均保持静音；文本限制为 1,200 个字符。

语音播放期间选择麦克风会中止音频，但绝不会调用会话停止或工具取消。实时语音会话会在播放完成或已完成轮次刻意保持静音后重新开启捕获，并提供独立的结束按钮；该按钮停止语音资源，但不停止任务。agent 轮次活动期间也可以开始捕获，识别出的后续消息使用普通队列。自动发送要求 composer 在捕获开始时为空并且之后没有变化；已有或并发键入的文本、附件、引用和斜杠命令会把转写保留在草稿中等待审核。待处理的人工交互和非普通 composer 事务仍是阻塞边界。切换 Session 和显式结束控制会推进生命周期 epoch、取消捕获与转写、停止语音、清空排队的语音回复，并让所有延迟到达的宿主回执失效。接纳或投影若有 30 秒仍不可观察，语音模式会以可见状态结束，但普通任务不会被取消。

状态驱动的光球、独立语音打断和如实工具活动借鉴了 [`eadmin2/jarvis_ai` 的 `88998de` 版本](https://github.com/eadmin2/jarvis_ai/tree/88998de8369e9d36f6d434b5e01feb93fcf1c33f) 中的交互模式。该实现是 Leon 原创代码；没有复制该仓库的源代码或 CSS。

## Alternatives considered

**采用外部 HUD 和 Hermes 服务器。** 否决，因为它会在 Leon 现有运行时旁增加另一套会话引擎、路由器、审批路径和 WebSocket 协议。

**合成每条 assistant 消息。** 否决，因为恢复的历史记录、键入工作、工具输出、代码和敏感操作文本不得在没有语音发起轮次时自行发声。

**现在捆绑 Piper 或克隆的神经语音。** 在首个版本中否决，因为已安装的 Piper 运行时涉及 GPL 分发影响，神经提供方会增加模型与硬件成本，并且参考语音需要明确权利。驱动接口保留了此未来选项。

**增加独立活动事件流。** 否决，因为 `ConversationSnapshot` 已包含权威事实，而第二条通道可能漂移或报告错误会话的状态。

## Consequences

Leon 现在无需另一个模型、GPU 分配、云端 TTS 调用或 agent loop，即可提供本地按轮连续语音、任务安全的打断和可见工作状态。浏览器与 Windows 的语音可用性决定首个提供方的声音质量；不捆绑自定义身份语音。音频片段转写和已完成回答播放并不是同时进行的全双工流，局部 STT/TTS 仍留待后续实现。宿主因果回执与有序回复协调消除了文本和时间歧义，而草稿比较交换、生命周期 epoch、投影超时和明确的交互门禁则防止过期语音或绕过审批。单元测试固定仅本地语音选择、取消传播、浏览器故障下的资源清理、超时、打断、实时重新聆听、会话隔离、精确轮次回复关联、乱序回执、并发草稿编辑、状态优先级和两个 slot 注册。组装后的 Web 验证仍负责浏览器集成、真实麦克风权限、声学行为和视觉回归覆盖。
