# Agent Note: 原生 web 工具的单次对外访问批准

Status: implemented

[English](2026-09-04-web-tool-outbound-consent.md) | 中文

## 问题

即使请求只是读取公共网站，搜索查询或 URL 也可能包含工作区的私人数据。文件系统隔离与使用外部模型的权限并不授权这次独立披露。通用执行前监听器也可能被更早返回 `allow` 的监听器绕过。

## 决策

[Web 工具消费方](../../../../packages/web/tool-web/README.zh.md) 拥有 `egressPolicy: ask | allow`。默认值为 `allow`；[Leon 预设](../../../../apps/cli/config/agent-presets/leon/agent.cordis.yml) 明确选择 `ask`。每个工具执行器在参数校验后、联系 `ctx.web` 前，请求新的、记入审计的 `allowed-once` 决定，除非当前会话拥有 [dsh-web-access](../../../../packages/web/web-access/README.zh.md) 的明确狭窄授权。这个后来加入的面向用户授权只对所在会话持久，仅适用于原生公开搜索和抓取执行器，`/web off` 会立即撤销；它不会改变全局批准策略。完整的不可变参数出现在审批理由中，因为并非所有客户端都会显示配对的非 shell 参数。不存在明确会话授权时，缺少服务、缺少 agent（智能体）、禁用提示、拒绝和无法回答均默认拒绝。等待决定后会再次检查取消状态。agent 调度器串行处理交互式调用；审批时间计入协作式工具超时。

现有 [Web 审批通道](2026-07-23-web-permission-and-approval.zh.md) 仍负责用户响应与审计事件对。[Web 能力 seam](../architecture/2026-06-24-web-capability-seam.zh.md) 保留提供方选择、传输和结果规范化。两项决策均保持活跃；此策略增加消费方执行约束，不替换其中任何机制。

## 考虑过的替代方案

**仅使用执行前监听器。** 更早的监听器可以短路 waterfall（瀑布式事件）。在实际原生工具执行器内检查，确保普通的执行前 `allow` 不等于对外访问批准。

**自动检测秘密。** 模式匹配无法可靠区分公共查询与私人项目上下文。逐次审阅较为保守且增加交互成本，但避免将分类器当作隐私证明。

**隐式的会话级或域名级授权。** 后续请求可以向同一目标披露新内容。基础策略仍只授权一次调用，绝不复用决定；后来加入的 `dsh-web-access` 能力是独立、明确且可见的每会话决定，只限这两个原生公开工具，不是推断出的授权或目标地址授权。

## 后果

提示显示实际对外参数，并在已有工具调用之外将它们记录到本地审批审计事件中。只有逐次获准的调用或刻意启用的 `dsh-web-access` 会话授权才会到达提供方；模型收到被保留的拒绝错误，而静态提示词和 schema 不变。现有通用消费方可以明确保留无需提示的 web 访问。

这不是完整的数据防泄漏。直接服务调用方、shell 网络访问、浏览器自动化、MCP、外部模型载荷和可信插件替换都不受此策略约束。自定义提供方和重定向仍需各自的安全要求。没有回答通道的无界面会话不能使用受保护的 web 工具，交互式审批会消耗配置的工具时限。

## 验证

聚焦执行器测试覆盖两个工具、所有非授权结果、缺少审批路由、禁用提示、重复调用、取消后迟到的授权、参数校验、明确的 allow 模式和 dispose（资源释放）。无密钥的[可运行示例](../../../../examples/headless-agent/web-approval.cordis.yml)快照经过真实 Loader、agent loop（智能体循环）、审批服务、工具执行和会话日志；只有脚本模型、用户响应与网络提供方被替换。合成的私人 canary 从不到达记录的提供方请求。真实浏览器交互与付费提供方行为属于单独验证工作。
