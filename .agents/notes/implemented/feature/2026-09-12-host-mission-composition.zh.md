# Agent Note: 推理前由宿主指定任务组合

Status: implemented

[English](2026-09-12-host-mission-composition.md) | 中文

## 问题

[持久审阅者身份规则](../bug-fix/2026-09-12-mission-reviewer-session-identity.zh.md)要求队友会话已存在，但原生成员创建会分配 UUID 并立即安排初始提示词。宿主需要在该提示词预留模型调用前完成职能身份分配。显示名称不能填补这项授权缺口。

## 决定

可选的 `hostComposition` 属于现有任务控制部署。宿主通过 `provisionTeam` 创建恰好两个 continuable 工作者，将 researcher 和 checker 职能分配给返回的原生会话 ID。创建状态和绑定与不可变额度、截止时间共同保存在任务记录中；任务仍仅以原生 Team 日志为真源。Ready 绑定必须匹配完整的三个会话名单，并排除重复 ID、创建失败及额外成员。模型或工具发起者作用域不能分配职能。现有静态审阅者 ID 配置仍受支持。

执行器在请求和流准入处等待 ready 绑定，即初始用户消息持久化后、取得推理（inference）slot 或预留预算前。可选 checker 职能预留额度解析为已保存 ID；实验性的八次调用变体不改变 48 次调用额度或十五分钟截止时间。拒绝准入不消耗调用。STOP 或暂停会取消正在创建的成员，保留部分会话，并阻止迟到的激活重新开放准入。关闭存储前会等待被取消的创建操作结束。

恢复只验证已保存绑定，不再次创建。持久 provisioning 状态若没有本进程已获准的创建操作，表示未完成，而不是活动进程的证据。它不能重置限额或自动创建替代工作者。暂停任务在宿主恢复前保持暂停。加载运行中的任务仍可能恢复先前已接受的 inbox 工作；在这种情况下，仅恢复职能不保证模型调用为零。

因此，离线检查和 STOP 直接读取现有任务表，不创建 agent（智能体）。`inspectStored` 不写入；`stopStored` 要求根会话不处于活动状态，并且在不发送生命周期通知的情况下提交终态取消。两个操作保留所有者和工作区检查，并拒绝模型或工具发起者作用域。宿主的独占目录锁仍然必需；此机制不提供跨进程协调。

## 考虑过的替代方案

**在 pre-step 钩子中等待。** Inbox claim 在该钩子前发生，但持久用户消息在其后追加。原生成员创建要求初始消息仍在等待或已持久化，因此延迟 pre-step 可能使宿主自己的启动流程死锁。

**先创建工作者再挂载执行器。** 工作者可能在执行检查器存在前进入推理，已经运行的 waterfall（瀑布式事件）链也不一定包含后来挂载的监听器。

**建立另一个任务或职能数据库。** 原生 Team 日志和现有任务领域已负责所需记录；额外的权威数据库会增加恢复歧义。

## 后果

实验运行时能在全部参与者绑定前以零适配器请求建立职能身份。宿主直接预留调用也拒绝未完成组合。此功能不授权 shell 访问，不提高模型推理能力，不批准产物，不完成任务，也不更新预算。失败可被检查，未完成的崩溃恢复明确要求操作者核查。

## 验证

针对性源码测试使用真实原生会话、名单、持久化、任务存储及执行检查器，并采用脚本适配器。覆盖推理前持久化、显示名称伪装、仅 checker 可用的预留额度、参与者自我分配、额外成员、ready 冷恢复、孤儿创建、STOP 保留及 dispose（资源释放）。离线测试检查只读字节不变、零 agent 激活、幂等 STOP 及重新加载的终态。这些测试证明运行时行为，不证明 GPU 性能；所属可运行示例提供完整 Loader 组合验证。
