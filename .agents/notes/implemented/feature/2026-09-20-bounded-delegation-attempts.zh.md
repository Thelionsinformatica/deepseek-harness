# Agent Note: 限额委派尝试

Status: implemented

[English](2026-09-20-bounded-delegation-attempts.md) | 中文

## 问题

要求只委派一次的提示词不能阻止子 agent（智能体）失败后的再次调用。要求工作 agent 不写入也不会移除其写入工具。

## 决策

下述全局工具限制由[审计工作 agent 准入](../bug-fix/2026-09-21-audit-worker-admission.zh.md)部分扩展：要求证据的进程内审计也会对宿主过滤器实施子作用域与嵌套执行检查。预算机制保持不变。

`tool-subagent` 中可选的 `maxCallsPerSession` 根据尝试在调用方会话有序工具调用历史中的位置决定准入。失败尝试消耗预算。恢复的事件保持相同的计数方式。缺少调用记录或已有结果记录的调用会在提供方启动之前被拒绝。

只读工作 agent 使用现有提供方的 `toolFilter` 允许列表。默认配置仍不设上限。限制覆盖一个会话中的一个工具名称，不覆盖其他委派工具或后续消息。持久化保持现有持久性保证；这不是恰好一次的崩溃恢复。

## 考虑过的替代方案

**仅靠提示词限制：** 被评估的模型违反指令重复委派并写入，因此文字不足以强制执行。

**第二个持久化计数器：** 复制会话日志会增加对账工作和另一个权威来源。现有有序事件已经标识尝试。

## 影响

宿主可以配置有界隔离评估而不改变正常委派。恢复和并发尝试具有确定的准入规则。测试使用脚本模型运行真实父级和子级循环，验证写入和重复委派被拒绝，但不能证明真实模型的能力。
