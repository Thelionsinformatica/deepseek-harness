# Agent Note: 已确认的个人访谈

Status: implemented

[English](2026-09-21-confirmed-personal-interview.md) | 中文

## 问题

个人记忆编辑器要求用户知道应该记录什么。引导式介绍让偏好更容易表达，同时不会把每次对话都视为存储个人信息的授权。

## 决定

`ui-work-dashboard` 中的 `GettingToKnowYou` 在个人记忆面板内提出五个可选问题。答案仅作为组件本地草稿保留。每个审查卡片只有在用户明确点击保存后，才使用现有的已确认个人记忆操作。问题与编辑后的答案一起存储，不经过模型推理。关闭会丢弃未保存的草稿；已保存条目仍可通过现有纠正与遗忘控件管理。

授权、敏感内容检查、所有者隔离、持久化与审计仍由宿主负责。记忆被禁用或处于只读状态时不能保存。客户端进行中保护防止单次保存期间的重复点击；结果不确定的失败会保留草稿，并提示用户重试前检查现有记录。这不是跨请求幂等性保证。偏好仅作描述，绝不改变权限。获准保存的记忆之后可能按照现有配置被召回给外部提供方，面板会披露这一点。

## 考虑过的替代方案

**从聊天自动提取。** 此阶段拒绝采用，因为它改变了同意边界，并引入依赖模型的解释，而不是保留用户的答案。

**独立的入门数据库。** 拒绝采用，因为个人记忆已拥有存储和生命周期操作。访谈是呈现层，不是另一个真源。

**完整的记忆图谱。** 暂缓，因为图谱需要经验证的关系和来源；介绍不会从个人答案推断这些内容。

## 影响

用户可以逐步提供偏好，无需模型费用，也不授予操作权限。组件卸载或刷新会有意丢失草稿。该界面是引导式表单，不是主动聊天，也不保证未来每次响应都会召回每条记忆。

## 测试

组件测试覆盖确认前不写入、编辑、跳过、丢弃、重复点击、保存失败和禁用写入。`apps/web/tests/personal-interview.e2e.ts` 使用隔离持久化验证实际 Web 组合，检查草稿不会出现在宿主存储中，并重新加载已确认条目。该测试不发送模型请求，也不验证模型召回质量。
