# Agent Note: 派生记忆相似图

Status: implemented

[English](2026-09-21-derived-memory-graph.md) | 中文

## 问题

持久记忆过去只是无序的记录集合：只读概览按作用域分组，`supersedes`/`supersededBy` 字段只承载时间谱系。没有任何派生结构把相关记忆连接起来，没有维护它的后台进程，搜索也无法触及与查询没有共同词项的相关记忆。

## 决策

`memory-local` 与 `personal-memory-local` 通过现有的 `OllamaSemanticIndex` 派生有界的成对余弦图；该索引新增 `api` 方言字段，覆盖 Ollama `/api/embed` 与 OpenAI 兼容 `/v1/embeddings` 端点。`linking.enabled` 在每次已提交的创建、纠正或遗忘之后安排一次去抖的服务端重建；读取从不触发计算。每个工作区或属主分区原子发布一份快照（各域内新增 `graph` 表，域版本不变），保存输入修订号映射、世代、算法版本、模型、参数以及钉在精确修订号上的边。快照状态区分 `pending`、`computed`、`empty`、`stale` 与 `failed`；没有索引的提供方报告 `unavailable`。更新的提交会递增世代，使过时的计算无法发布任何内容。搜索在请求的剩余额度内追加边邻居，不挤占直接命中，且仅在 `computed` 快照上进行。边标注为派生相似关系而非事实关系；个人与工作区分区独立计算，绝不跨属主或跨工作区连边。两个只读管理端点（`memoryGraph`、`personalMemoryGraph`）把快照投影到浏览器而不暴露工作区或属主 id，概览面板在现有分组图中绘制已发布的边。

## 可靠性边界

发布使用 domain 修改队列，并在写入执行时及完成后重新校验世代与有效修订。成功事件必须在持久写入后发出，丢弃的计算不会产生成功事件。后端拒绝被收敛为 `persistence-failed`；观察者不能把已保存的图变为故障。dispose 在关闭 domain 前等待推理及已提交写入。启动包含只有图的空分区，定时器处理到期和未来修订切换，无需读取触发调度。个人记忆禁用会暂停图处理，包括启动与进行中的工作。未来纠正生效前，有效历史修订仍可参与；显式历史搜索不会沿当前边扩展。

嵌入响应要求整数索引与输入一一对应、错误正文有界并拒绝重定向。算法版本 2 对完整文档分段，并在明确边界内自适应拆分过大批次和单个输入；耗尽限制后仍报告 `INPUT_TOO_LARGE`，不截断事实。[有界恢复决策](../bug-fix/2026-09-25-bounded-memory-graph-recovery.zh.md) 负责说明对原有仅整篇文档失败策略的替代。界面健康状态独立于图内容，仅展示 computed 且修订匹配的相似边。本地端点本身不能证明本地推理：部署必须核实进程并禁用远程代理。

## 已考虑的替代方案

**外部图服务（Graphiti、Mem0）。** 本版本拒绝：它引入 Python 与图服务器以及实体三元组的 LLM 抽取，而已验证的本地嵌入端点已经提供相似度信号。经用户确认的结构化关系可以在之后叠加，无需抽取模型。

**逐边写入而非快照。** 拒绝：部分写入的边集合无法原子失效，过时的计算可能重新引入已纠正或已遗忘的记忆。

**读取触发（惰性）计算。** 拒绝：打开检查面板必须保持纯读取，否则每次查询都会重新嵌入。

## 后果

图状态是可由权威记录重建的派生数据；删除 `graph` 表不会丢失记忆内容。嵌入工作在专用本地端点上运行，不与对话模型加载器争用。瞬时提供方故障会记录 `failed` 并进行有限的计划重试，绝不由读取触发重试。重建失败保留先前快照覆盖范围及失败状态。各部署按嵌入模型选择 `linking.minScore`；Leon web 配置档使用 0.75，来自实测的 pt-BR 间距（相关对 0.805-0.891，无关对 0.646-0.692）。这些整篇文档测量不能校准新的长文档分段均值。

## 验证

单元测试覆盖 OpenAI 兼容响应的排序与拒绝类别、边的规范顺序、阈值与每节点上限以及按修订号键控的缓存。调度器测试覆盖原子发布、基于世代的过时计算丢弃、纠正/遗忘后的边移除、播种时的工作区隔离、无读取触发重试的故障记录以及去抖前的处置。提供方组合测试覆盖 pending/computed/stale 生命周期、同一介质上的重启持久化、不暴露作用域 id 的管理端点投影、属主分区隔离，以及搜索扩展在嵌入端点宕机时仍返回词法查询遗漏的边邻居。这些检查不度量真实语料上的召回质量；该证据由 LEON-EVAL-PTBR 负责。

`graph-lifecycle.spec.ts` 覆盖延迟或拒绝的持久化、禁用、时间边界、观察者故障与 dispose。`graph-durable.spec.ts` 使用生产 Loader 和 JSON 存储，关闭并重新打开同一临时目录，验证磁盘上的修订绑定边与空分区恢复。`graph-config.spec.ts` 在打开存储前拒绝无效边界。这些测试使用确定性嵌入；部署的真实 Nomic 批次探测是独立证据，不代表模型质量已验证。
