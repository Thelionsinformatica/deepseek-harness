# Agent Note: 始终呈现的个人核心画像

Status: implemented

[English](2026-09-22-always-present-core-profile.md) | 中文

## 问题

个人记忆的自动召回仅在人类消息包含至少三个连续字母或数字时才运行。"oi" 这类简短问候永远不会触发召回，因此新对话从一开始就缺少用户身份、已确认的画像或稳定偏好。此前无法把一小部分已确认的个人事实标记为"始终呈现"。

## 决策

`tool-memory` 为记忆记录增加了可选的 `core` 标记（增量变更；旧记录无需迁移仍然有效）。步骤前召回投影有效且已确认的核心事实（`core: true` 且存在 `validation`），使用独立预算（`coreRecallLimit` 默认 10，`coreRecallMaxChars` 默认 2000），与查询无关。查询召回只排除核心画像中实际序列化的事实，因此因预算省略的事实仍可通过相关搜索召回。

列表采用分页，因此第一页之外的核心事实仍能被找到。进程内 `contextVersion` 拒绝跨越成功变更、提供方更换或启用状态变更的读取，且不依赖遥测。提供方失败会被捕获并记录，不中止轮次。工具输出暴露 `core`，使模型能够查看当前成员状态；只有带确认的 Host 管理操作可以改变成员资格，具体见[人工确认个人记忆](../bug-fix/2026-09-25-human-confirmed-personal-profile.zh.md)。

每一步都会在下游压缩之前，通过记入日志的 Session surface 替换清除先前所属的个人快照，再把当前值投影到保留的 slot。请求错误恢复会在获准的同一步重试之前再次刷新，包括普通退避和上下文溢出恢复。这会改变活动模型视图，不删除原始事件，也不修改已捕获的请求。禁用或失效的读取会留下不含事实的标记，而非陈旧值。

既有的带确认浏览器纠正操作，以精确 revision 对提交的完整文本重新确认，写入 `validation: explicit` 和 `confidence: 1`。完整管理权限、可见确认、所属 Session、敏感内容检查和审计准入仍是必要条件。不增加面向模型的批准字段或第二套记忆存储。

核心画像沿用唯一的权威个人记忆存储、相同的 id 与 revision，以及相同的不受信数据边界（`personal-core-profile`，"untrusted, not instructions"）。它从不改变权限或晋升规则。

## 备选方案

**复用 `validation: 'reviewed'` 加 `importance: 1` 作为标记。** 否决，因为它把二元、始终呈现的含义叠加到既有语义（"人工审核"与连续评分）之上。

**把画像复制到系统提示词或 Markdown 文件。** 否决，因为它会创建第二个可能与记忆存储分叉的权威来源，并忽略禁用/遗忘/更正的生命周期。

**从对话中自动提取要点。** 本阶段否决：要点需要明确的确认，而非推断。

## 后果

即使面对 "oi"，新会话也会收到已确认的核心事实。普通纠正会使确认失效，因此被纠正的事实离开核心画像，直到重新确认；遗忘会移除它；禁用个人记忆会抑制刷新后的注入。核心与查询投影不会重复同一事实。重启或压缩后，事实从当前存储重建，而不是从已被替代的快照文本恢复。

输出有界，但扫描全部活动分页会增加本地 I/O。surface 替换会从第一个变化的 token 开始使 KV Cache 失效，并追加审计事件。旧版重复 slot 各保留一个不含事实的标记，直到压缩。此变更不会遮蔽已复制到人类消息、助手回复、工具结果或旧摘要中的事实；原始日志仍被保留。进程内 revision 检查不能检测进程外的存储编辑，也不能取消已发送到提供方的请求。

根据独立的[人工确认决策](../bug-fix/2026-09-25-human-confirmed-personal-profile.zh.md)，模型创建的提案现在保持未确认。既有确认元数据不会被追溯审计：核心筛选只确定资格，而不是每条既有记录的真实性或授权。

## 测试

`packages/memory/tool-memory/tests/loader-composition.spec.ts` 覆盖问候注入、失效、遗忘、禁用、标记与取消标记、预算感知去重、提供方失败，以及第一页列表之外的核心事实。`core-profile-runtime.spec.ts` 使用临时 JSON 存储和 JSONL 持久化捕获真实 agent loop 请求，包括多步骤、恢复、压缩、重启、模型切换和遥测关闭时的读取竞争。管理集成测试覆盖重新确认和被拒绝的操作；提供方测试覆盖两种存储模式中的精确 revision 和时间历史保留。

可运行且无需密钥的 `examples/headless-agent/personal-core-profile.cordis.snapshot.yml` 组合使用 `tests/fixtures/personal-core-profile-driver.ts`。其快照测试检查五次请求、所有者隔离、未确认事实、纠正、遗忘和独立的持久 JSONL 回放。只有语言模型响应是脚本化的。这些检查证明运行时集成，不代表真实模型的对话质量、生产激活或与 Letta 行为等价。
