# Agent Note: 持久化的按配置 skill 可用性

Status: implemented

[English](2026-09-25-profile-skill-selection.md) | 中文

## 问题

已安装的 skill 可以在输入框中发现，但用户无法在设置中管理其可用性。隐藏输入框条目无法阻止模型加载器、显式调用或配置的自动加载。编辑共享 skill 文件也会影响其他配置。

## 决策

现有的 `agent-presets` 设置命名空间拥有 `disabledSkills`，将 preset id 映射到 skill 名称数组。缺失条目保持现有可用性。设置中的 Skills 区域列出所选配置及可选已注册工作区的已安装元数据；工作区只改变发现范围，不改变配置级策略。写入使用现有的修订检查 `settings.mutate` 约定，并保留当前清单中不存在的禁用名称。

每个常驻 preset 挂载向 `ctx.skills` 注册实时限制。限制在全局与继承作用域链中累积；更近的作用域不能覆盖拒绝。`snapshot()` 和 `list()` 隐藏不可用的 skill。`get()` 在发现之后、加载正文之前检查可用性，并在异步加载之后再次检查，不提供绕过选项。设置提供方释放时保留最后确认的限制，不会在清理期间启用 skill。

`inventory()` 返回包含禁用 skill 的元数据，而不是定义。仅限回环的 `skill.catalog` RPC 通过常驻组合解析 preset，通过宿主注册表解析工作区，不会启动或恢复 agent。若发现期间设置修订或 preset 代际发生变化，它会拒绝该次观察。来源标签会规范化；不会返回正文或文件系统路径。

本决策扩展了 [skill 系统](2026-07-05-skill-system.zh.md)和[调用策略决策](2026-07-28-skill-invocation-policy.zh.md)。两者仍保持有效：发现与 frontmatter 调用策略继续独立拥有其职责。可用性是额外限制，绝不覆盖 `modelInvocable` 或 `userInvocable`，也绝不代表执行授权。

## 曾考虑的替代方案

**只在浏览器中隐藏禁用条目。** 否决，因为其他消费方仍可能加载其正文，显示状态将无法描述宿主行为。

**重写每个 skill 的 frontmatter。** 否决，因为共享文件可能服务多个配置，升级可能替换它们，而且文件编辑没有现有的设置修订保护。

**保存第二份目录或浏览器本地偏好。** 否决，因为可用性属于宿主持久化的配置策略。注册表仍是唯一发现机制，Settings 仍是唯一偏好存储。

## 后果

选择在宿主重启后保留，适用于继承同一常驻配置的子 agent，不改变默认 preset 或其他配置。并发编辑会收到明确冲突，而不会覆盖更新的设置。发现不完整和只读设置均有可见的 UI 状态。

禁用影响后续读取与加载；不会删除已记录在对话中的指令，也不限制独立文件系统工具。发现不完整时，消费方可能保留之前的目录摘要，但禁用正文仍无法加载。外部目录安装、包审查和沙箱权限变更不属于本次交付。

注册表、消费方、preset、API 和客户端测试固定这些边界。隔离的 `apps/web/tests/skills-settings.e2e.ts` 使用真实 Loader、文件设置、传输和 Chromium，不挂载模型适配器；它测试开关、宿主执行、页面重新加载、同级配置独立性以及可访问 UI 快照。
