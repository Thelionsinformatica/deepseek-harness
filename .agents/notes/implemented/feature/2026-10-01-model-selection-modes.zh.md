# Agent Note: 明确的模型选择模式

Status: implemented

[English](2026-10-01-model-selection-modes.md) | 中文

## 问题

输入框把自动分类与固定协调者的部署配置混在一起，因此显示的模型可能不同于获准请求所用的模型。仅提供方名称也会隐藏通过另一账户提供的模型，而目录并不能证明配额或执行质量。

## 决策

现有的会话级模型目录提供可搜索的提供方分组和 Host 所拥有的元数据。可选字段 `selectionMode` 区分 `manual`、`adaptive` 和 `team`，现有 `automatic` 字段保持兼容。Manual 使用明确选择的路由。Adaptive 按声明的层级分类每个获准提示词，不受部署的协调者默认值影响。Team 对文本使用已配置的协调者，对图像请求使用明确的视觉角色。

Host 通过 `coordination` 投影已配置的协调者、执行者、复核和视觉角色。选择 Team 不会生成协作者、要求每次聊天复核或合并模型答案。现有委派机制和客观完成检查保留这项责任。更换模型或模式会清除可能覆盖新选择的待处理路由决策。

明确的手动选择仅改变当前会话，不改变全局配置的协调者。不含 `selectionMode` 的旧版请求保留之前保存默认值的行为。空闲的 Team 目录在准入锁内解析已配置的协调者，不展示过时的历史路由。

选择器显示已提供的输入模态、上下文容量、默认输出上限和推理强度选项。缺失的元数据和价格保持未知。声明的容量不代表质量或账户可用性。命令选择与输入框选择使用相同的目录和 RPC。

模式选择仅在当前进程有效。重启恢复部署默认值；现有请求事件保留最后请求路由，不保留用户的模式选择。界面明确说明这一限制，不添加会话格式事件。

## 考虑过的替代方案

**只重命名自动路由，不改变请求准入。** 已否决，因为固定协调者的部署仍会阻止自适应分类。

**在菜单后实现新的融合编排器。** 已否决，因为配置角色并不意味着并行推理、聚合或经过验证的复核。缺少执行约定时，选择器不得宣传这些行为。

**用新的会话事件持久化模式选择。** 已推迟，因为旧版读取器和回滚兼容性需要单独的会话格式决策。当前界面改为说明进程生命周期限制。

**从模型名称推断价格和能力。** 已否决，因为相同的模型标识可以使用不同的提供方、账户和实际配置。

## 影响

选择现在表达不同的准入行为，不创建第二个目录，也不改变模型权限。不可用的已声明模型在推理前失败。账户配额和提供方参数行为仍需单独在线验证。持久化模式选择和保证集体执行不属于本功能。

## 测试

聚焦客户端测试覆盖搜索、元数据缺失、键盘操作和模式提交。Host 测试覆盖路由和陈旧队列失效；真实 Loader 组合用合成提供方测试网关与 agent loop（智能体循环）。在线提供方和完整浏览器证据记录在部署报告中，而非这些不需要凭证的约定测试中。
