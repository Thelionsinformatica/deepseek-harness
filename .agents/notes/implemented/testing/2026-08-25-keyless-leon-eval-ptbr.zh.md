# Agent Note: 无需密钥的 LEON-EVAL-PTBR 阶段验收

Status: implemented

[English](2026-08-25-keyless-leon-eval-ptbr.md) | 中文

## Problem

Memory V2 已有可靠的包级与组合测试，却没有一个统一、可复现的阶段决定。证据分散在存储、工具、Loader、上下文组合、路由和 bundle 套件中，既不报告三次运行稳定性，也没有共同的延迟与内存预算。第二套手写基准实现会偏离生产测试，而强制真实模型运行又会把模型波动、凭据、成本和硬件依赖带入隔离与隐私决定。

## Decision

[`scripts/leon-eval-ptbr-model.ts`](../../../../scripts/leon-eval-ptbr-model.ts) 负责 31 个命名的 PT-BR 场景，并把每个场景映射到现有 Vitest 的精确证据。只有在证据清单缺少跨会话连续性、无关查询回忆或事实与建议分类时，注册表才新增专用用例。workspace 与用户隔离使用独立夹具身份和精确允许列表；云端场景检查不含内容的路由事实与显式外部策略，而不发送请求。

`pnpm run test:leon-eval` 使用单个 worker 将所需证据运行三次。自定义 reporter 只保留文件与测试身份、状态、耗时、Vitest 堆内存诊断和进程 RSS。协调器拒绝格式错误的报告、缺失证据、不完整的基线次数、场景失败、不稳定的 oracle 或召回率，以及高于 2,000 ms 或 512 MiB 的资源 p95。它把脱敏聚合结果写入被忽略的 `.artifacts/leon-eval-ptbr/latest.json` 路径。

跨 workspace 隔离、跨用户授权、不含内容的外部路由、提示词注入限制和语义预过滤场景被标记为关键场景。它们的失败单独可见，并始终让命令失败。其他场景失败也会让阶段失败；关键标签可防止未来的聚合策略把安全证据当作普通分数权衡。

无需密钥的结果证明 Leon 的确定性行为，而不证明模型回答质量或本地 GPU 吞吐量。路由用例证明所选择的已配置层级与推理强度。语义用例使用受控 loopback 端点。在特定部署的真实 Ollama 运行确认目标机器上的冷启动、吞吐量和 embedding 质量之前，交付的语义开关保持关闭。

## Alternatives considered

**为所有场景创建独立的端到端基准实现。** 已拒绝，因为重复的存储、回忆和策略夹具可能与已经约束交付行为的包级和真实 Loader 测试不一致。

**阶段验收必须使用 Ollama、Gemini 或 OpenAI。** 已拒绝，因为提供方可用性、变化的模型输出、凭据、成本与主机硬件会让隔离和隐私验收不确定。真实模型质量保留为单独的部署 profile。

**接受一次成功运行。** 已拒绝，因为一次通过无法发现不稳定的证据选择或资源波动。三次连续基线是最小接受结果。

**为了调试在报告中发布提示词和失败内容。** 已拒绝，因为隐私评估不应创建另一个记忆内容、用户数据、workspace 身份、凭据或模型响应存储。

## Consequences

Memory V2 获得一个具有安全硬失败语义和量化本地证据的可重复命令。精确测试名称映射会在证据被重命名或删除时有意失败，迫使场景注册表与其含义一起接受审查。该套件复用成熟测试，因此无需 API 即可快速运行，但其延迟和堆内存数据衡量的是确定性操作与测试框架开销，而不是最终用户看到的模型延迟。在默认启用语义检索之前，仍然需要真实硬件 profile。
