# Agent Note: 关闭式失败的 LEON-ACCEPTANCE-7 产品证据

Status: implemented

[English](2026-08-26-leon-acceptance-7.md) | 中文

## Problem

Leon 已有连续性、记忆、workspace 隔离、Windows 自动化、完成治理、本地路由和成本展示的包级证据，但这些测试没有共同回答一个产品问题：七项所需能力是否都在同一版本上获得证明。非正式审核可能把一个通过的微测试当作长期自主工作流的证明，忽略被跳过的 Windows 证据，把估算成本称为精确成本，或者在收集诊断时暴露凭据与模型内容。真实云端模型验收还会把提供方可用性、成本和可变输出引入本可在本地决定的主张。

## Decision

[`scripts/leon-acceptance-7-model.ts`](../../../../scripts/leon-acceptance-7-model.ts) 负责七项命名产品标准，并把每项主张映射到现有 Vitest 的精确用例。证据被标记为决定性或辅助，标准被标记为关键或非关键；即使可执行证据通过，已命名覆盖缺口也会强制产生 `partial`。缺失、跳过、待处理、改名或失败的证据会强制产生 `failed`；精确测试身份使削弱证明必须经过显式注册表审核。

`pnpm run test:leon-acceptance` 使用一个 worker 且不启用文件并行，将完整证据清单运行三次。只有每项标准在每次重复中通过、运行结果稳定、至少存在三次重复且没有标准处于部分状态时，聚合结果才通过。即使脱敏聚合无法把某个子测试失败表示成映射证据，只要子测试失败，命令也会以失败状态退出。

本地执行标准在每次重复中启用真实 loopback Ollama profile。它通过精确的 `qwen3.5:9b` 与 `ornith-1.5:9b` id 验证 30 个固定 PT-BR 微任务答案，因此最少执行 90 次本地推理；与此同时，路由哨兵会在适配器调度前拒绝外部提供方。完整产品决定在 Windows 上运行，因为其精确窗口 UI Automation 证据是原生能力，在其他平台会被跳过。

LEON-ACC-005 使用决定性用例 `learns reviewed successful tool evidence and reuses exact steps after a model switch`。流程候选只能包含成功的 `tool/call` 及其匹配的成功 `tool/result`，并可在审核前以候选状态持久化；人工审核会在提升或复用前批准一个精确命令。之后，运行不同模型的新会话会在持久前置条件和重新验证状态约束下检索并实际执行步骤与验证器。

操作过程、七项证据范围、模型前置条件和结果语义位于 [LEON-ACCEPTANCE-7 参考](../../../../docs/evals/leon-acceptance-7.zh.md)。

## 证据与保密性

协调器会在启动 Vitest 前移除受支持的 DeepSeek、Gemini、Google、NVIDIA、OmniRoute 与 OpenAI 凭据环境键。真实模型测试只接受 `127.0.0.1` 或 `[::1]` 上不带身份验证的 HTTP 端点。不含内容的 reporter 会把测试文件、精确测试名称、状态、耗时、可选堆内存用量和进程 RSS 写入临时报告，并在聚合后删除这些报告。

持久聚合结果包含标准身份、状态、耗时、已命名缺口，以及缺失或失败证据，不包含提示词、响应、会话、窗口内容、凭据或错误堆栈。单独的本地 Ollama 产物存储规范化答案的 SHA-256 摘要与数值任务证据，而不是答案文本。两个产物都是诊断证据，不是新的记忆或 transcript（文本记录）存储。

## 解释限制

本地基准执行受约束的单答案推理和精确 oracle；它不执行 Leon agent loop（智能体循环）、工具、文件编辑、自主恢复或最终项目验证。因此，它为本地模型标准提供支持，但不声称等同于长期的 ChatGPT Work 风格任务。

会话成本测试会区分提供方报告的 nanodollar 金额、根据已配置 token 价格得出的估算，以及缺少充分核算证据的调用或 retry/failover 尝试。它们不会核对发票、账户账本、额度、税费、协商价格或被提供方省略的费用。

流程候选尚未自动生成，也没有专用审核界面。这些是自动化与可用性限制，并不是 LEON-ACC-005 所覆盖的显式候选与批准流程缺少证明。

三次串行重复会在测试结果层面检测缺失证据与多次运行分歧。它们不证明浸泡可靠性、更换权重或量化版本后的模型稳定性，也不证明跨硬件延迟等价。Windows UI Automation 仍是平台要求，而不是可移植模拟。

## Alternatives considered

**接受一次成功的证据运行。** 已拒绝，因为一次通过无法暴露被跳过的平台用例、瞬时本地模型结果或不稳定证据清单。三次连续重复在不引入并行竞争的前提下提供最小重复观察。

**使用 Gemini、OpenAI 或其他云端模型作为验收裁判。** 已拒绝，因为凭据、成本、提供方可用性与可变模型判断会使结果既不本地也不可复现。云端凭据会被移除，而不是仅仅不使用。

**仅通过路由 fixture 证明本地模型使用。** 已拒绝，因为分类器决定不能证明所选本地模型能够回答代表性语料。真实 Ollama profile 在保持 loopback 调度的同时增加受约束答案证据。

**把 30 个本地微任务视为完整自主执行的证明。** 已拒绝，因为语料既不调用工具，也不执行端到端 agent 工作流。该限制保持明确，而不是夸大本地推理结果。

**为了诊断存储原始提示词、答案和失败堆栈。** 已拒绝，因为验收过程不得创建另一个用户内容、凭据、模型响应或机器状态仓库。哈希、计数器、证据身份与稳定错误代码足以支持该决定。

## Consequences

Leon 获得一个评估全部七项主张的可复现命令，并在任何证明部分成立、缺失、跳过或失败时拒绝批准。精确名称注册表会有意与测试含义耦合，因此合理重构必须更新证据决定，而不能继承静默通过。最小运行成本相对较高，因为它执行 90 次本地推理，并要求 Windows 和两个精确 Ollama 模型 id，但它不会产生云端 API 费用，且会发出经过脱敏、可审核的产物。

当决定性的模型切换用例存在并在每次重复中通过时，LEON-ACC-005 不再产生部分结果。自动创建候选与专用审核界面仍是未来产品改进，而精确命令批准、经验证的跨会话执行、持久前置条件和重新验证已经属于获证明的显式流程。
