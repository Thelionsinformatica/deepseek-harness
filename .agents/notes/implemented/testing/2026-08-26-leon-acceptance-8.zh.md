# Agent Note：由宿主验证的 Leon 长自主任务基准

Status: implemented

[English](2026-08-26-leon-acceptance-8.md) | 中文

## 问题

LEON-ACCEPTANCE-7 通过确定性包测试和受约束的本地模型微任务证明七个产品边界。这些用例并不证明真实 Leon runtime 能规划项目变更、通过工具检查和编辑多个文件、执行测试、从缺陷中恢复，并生成能通过独立预言机的完成证据。若使用脚本控制器向 LLM 请求 JSON 动作，就会产生虚假阳性：真正拥有执行权的是控制器，而不是 AgentLoop 和 ToolRuntime。若信任位于模型可写 workspace 内的 journal 或完成 receipt，受测主体就能伪造自己的证据。

云端裁判会引入凭据、费用、可变的提供方行为和意外内容传输。把隐藏测试放在可见 workspace 内会泄漏诊断目标。仅为回答通过或失败而保留原始会话，又会形成一个包含提示词、源码、工具结果和本地路径的第二存储。

## 决策

[`scripts/run-leon-acceptance-8.ts`](../../../../scripts/run-leon-acceptance-8.ts) 针对一个隔离 fixture 运行两个全新且真实的 `headless` Leon 组合。第一个精确本地模型负责规划、文件检查、多文件实现和可见测试执行。宿主持有且位于 workspace 之外的预言机必须先通过，然后宿主注入一个规范的舍入回归；同一预言机随后必须失败。第二个全新组合在现有 fixture 上使用另一个精确本地模型，负责诊断、修复和可见测试执行；宿主预言机最终必须通过。

控制器只负责 fixture 建立、本地模型可用性检查、进程和时间边界、故障注入、隐藏预言机执行、会话日志投影、最终评估、清理和产物发布。它绝不把模型文字翻译为文件编辑或命令。Leon 的动作会经过真实 AgentLoop、ToolRuntime、文件系统、todo 和 shell 服务。接受的 shell 表面只有精确的 `node --test`；所有文件变化都使用 Leon 原生工具。

[`scripts/leon-acceptance-8-model.ts`](../../../../scripts/leon-acceptance-8-model.ts) 是失败关闭的证据所有者。它要求首次调用是至少含五项的 `todo_write`、至少两个必需源码文件发生变化、两个阶段都有模型执行的成功测试、恢复阶段先出现失败测试再出现后续通过测试、本地路由证据、规范注入源码哈希、预言机源码哈希与对应阶段精确源码哈希相等、注入故障被发现、被修复源码发生变化且最终预言机通过。受保护文件哈希、意外条目、workspace 外文件引用、未知工具和任何非精确测试命令的 shell 调用都是拒绝输入，而不是警告。

每个阶段都有一个 turn、模型 step、工具调用、token 和墙钟预算。进程超时是主动宿主边界；从事件推导的限制会在已完成会话超出时使报告失败。确定性单元测试无需调用模型或外部 API，即可覆盖端点限制、无内容事件投影、fixture 的失败和通过状态、完整正向证据，以及对绑定或策略的对抗性失败。

## 隔离与证据所有权

runtime 子进程接收环境变量白名单，不继承外部凭据和代理变量。其调用目录与 DSH home 都是新的临时目录，因此项目和用户 `.env` 层不会导入操作者 API 配置。临时 overlay 只声明一个 Ollama 提供方和模型，禁用 settings 和 credential 变更，并移除 web、jobs、skills、code runtime、goals、workflows、Ralph、OpenCode 和进程内 subagent。

隐藏预言机存放在会话 workspace 之外，提示词从不包含其名称。workspace sandbox 限制修改，同时证据投影还会拒绝解析到 fixture 之外的文件系统参数。受测主体无法通过写入 `.json`、JSONL 或其他 receipt 来满足完成条件：只有宿主观察到的持久事件、宿主运行的预言机退出码和宿主计算的哈希会进入判定。

runner 会在原子写入结果之前删除 fixture、DSH home、隐藏测试和原始 transcript。持久产物包含稳定失败代码、计数器、时间、模型身份与摘要、相对源码名称、事件序号和 SHA-256 哈希；不包含提示词、模型响应、源码文本、工具参数和结果、临时绝对路径、隐藏测试文本、凭据或堆栈。

## 考虑过的替代方案

**在 Leon 外部使用 JSON 动作解释器。** 拒绝，因为它测试的是 LLM 加定制控制器。控制器会选择并执行文件系统和测试操作，绕过自主性声明所指向的 Leon 服务。

**保留模型写入的执行 journal 或完成文件。** 拒绝，因为可写 fixture 内的任何文件都能被伪造、重排或在最后一次测试通过后更改。宿主侧持久事件和预言机哈希不受主体控制，并把证据绑定到源码状态。

**告诉模型要修复的文件和缺陷。** 拒绝，因为那只测试按流程表演。恢复提示词只说明验证发现回归；可见测试和当前源码才是模型的诊断输入。

**把第一次可见测试通过视为完成。** 拒绝，因为模型可以在通过后继续编辑，或只满足暴露用例。受保护隐藏预言机会在每个相关源码状态后运行，最终通过还必须绑定摘要。

**运行 Gemini、OpenAI、OmniRoute 或 LLM 裁判。** 拒绝，因为外部凭据、费用、网络状态和可变判断都没有必要。两个受测模型和全部推理都保留在字面回环 Ollama 上。

**从这个 fixture 声称任意长周期自主性。** 拒绝，因为一个分阶段订单汇总任务不足以支持该结论。基准被明确限定为有边界的故障注入 lane，并在参考文档和产物语义中保留此限制。

## 后果

Leon 现在拥有一个可复现的验收 lane，它测试真实 agent 和工具栈，而不是只测试响应的模型 harness。一次通过证明所选本地模型完成了这个有边界的多阶段流程，并且其完成声明与受保护的独立证据一致。失败同样有价值：稳定代码能够区分规划、工具、路由、预算、隔离、注入、预言机和完成缺口，而不保留敏感诊断内容。

模型层的基准刻意较慢且具有非确定性。它使用两个全新会话和宿主注入故障，因此证明模型变化后的 workspace 连续性，但不证明同一会话恢复或自然缺陷发现。单次运行不能证明统计稳定性，一个 fixture 也不能近似所有 ChatGPT Work 任务。后续可通过重复运行和添加更多受保护 fixture 扩大信心，而无需削弱本 gate。
