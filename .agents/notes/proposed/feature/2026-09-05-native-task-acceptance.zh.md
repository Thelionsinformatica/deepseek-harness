# Agent Note: 原生精确任务验收

Status: proposed

[English](2026-09-05-native-task-acceptance.md) | 中文

## 问题

读取成功且轮次结束后，交付的值仍可能被截断。全局完成声明检测刻意不检查普通答案。

## 提案

[completion-claim-policy](../../../../packages/guard/completion-claim-policy/README.zh.md#exact-task-acceptance) 中需显式启用的实现，将可信的精确输出标准绑定到用户消息，在轮次停止前检查最终答案。它把标准和决定存为会话事件，使用有界原生 steering（中途引导）而非外部控制器。源码实现和无需密钥的 Loader 场景已存在；生产启用仍暂缓。

## 考虑过的替代方案

根据工具成功推断正确性会重现缺陷。让执行器自行选择预期答案无法提供独立验证。强制每次回答都调用第二个模型会产生费用，仍不能保证真实。精确标准覆盖确定性任务，并明确不验证开放式答案。

## 验收标准

验证精确答案、缺失和失败的读取、错误文件目标、重试耗尽、任务隔离、歧义排队消息、回放、HMR（热模块替换）及重复停止回调。组装 Loader 的 transcript（文本记录）必须显示同轮修正和失败，并保持模型可见文本稳定。投入生产前仍需原生本地推理（inference）、崩溃恢复、两种 SDK 事件投影及 UI 集成。

## 风险

函数式算术验收是精确哈希之外的可选方式。它使用封闭的二元表达式语法，不移植 Python AST 试点，也不启动模型生成的代码。它刻意收窄可用语法，以消除可执行验证器和外部运行时。可信数值示例可在有界、已记录的同轮恢复中展示给模型；不提供标准表达式。通过有限示例不等于普遍正确，浮点数采用精确相等比较。API 准入和持久化重建拒绝混合标准，并要求只读执行。现有验证事件名称和原因不变；生产 UI、通用项目验证器及推广仍暂缓。

只读候选实现增加显式可信的 `readOnly` 标准，经 RPC 传入持久化任务元数据。执行器现有的单调守卫在该开放轮次中拒绝 read/glob/grep 之外的所有工具，包括恢复和额外用户消息；下一普通轮次不变。它刻意阻止 shell 和委派，而不是信任其描述。它不覆盖插件直接 I/O 或后台工作，也不是操作系统沙箱。单元和 Loader 测试必须证明工具体执行前即被拒绝。生产启用和 UI 权限选择器仍暂缓。

保存在 `D:/Leon/audits/baseline-pilot-20260905-222307` 的隔离本地试点通过了 15 个严格案例中的 8 个。另一次四案例恢复探测修正了两个答案，另外两个耗尽有界重试；这不是统计可靠性估计。2026-09-06 的恢复文本候选版本显式检查所需格式和完整输出单位，同时保留用户请求的 JSON 格式及禁止文件编辑的要求。它不暴露预期答案，也不改变路由、预算或外发同意。该候选版本的真实模型比较仍待完成；确定性测试本身不能证明改善。

客户端运行时按根会话提示词转发显式标准，不保留会话默认值，也不把预期答案混入模型内容。两种子会话模式都在传输前拒绝标准，并为输入框保留错误。运行时测试覆盖请求隔离、子会话拒绝和宿主错误传播；输入框草稿事务和标准编辑器仍待完成。

UI 投影区分暂时通过与已完成验证的轮次，并对普通轮次隐藏验证。实时、回放和取消状态测试覆盖此投影；浏览器视觉验证及聊天标准编辑器仍待完成。宿主通过空闲且收件箱为空的排队请求，将显式标准准入到 `session.prompt`，并解析隔离预设的服务。一次经预设 `leon` 的真实本地 llama.cpp 运行在首次尝试中通过精确答案和必需读取检查。该运行不能证明模型出错后的实时恢复。宿主和客户端构建以及 88 个定向测试通过。

流式传输可能在验收前显示答案；消费方不能把首段文本或仅有 turn/end 视为证明。预期答案哈希不是秘密存储。读取结果证明执行，不证明文件新鲜度。RPC 标准使用宿主现有授权和有界输入验证，不授予新权限。恢复来源可以启用既有的模型恢复路由，但不能授予外发同意。
