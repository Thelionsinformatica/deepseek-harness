# LEON-EVAL-PTBR

[English](leon-eval-ptbr.md) | 中文

## 目的

LEON-EVAL-PTBR 是 Memory V2 的可执行、无需密钥的阶段验收，用于验证连续性、安全性、隔离、治理、本地优先路由与可选语义检索。凡语言会影响行为的场景都使用巴西葡萄牙语输入，并引用一个确定性的 Vitest 精确用例，而不是复制第二套夹具实现。

## 运行评估

```sh
pnpm run test:leon-eval
```

协调器使用单个 worker 将规范场景证据运行三次，采集测试耗时与堆内存诊断，并把脱敏报告写入 `.artifacts/leon-eval-ptbr/latest.json`。`--runs N` 接受不少于三次的重复运行，`--output <path>` 可选择其他报告文件。

当证据缺失、任一场景失败、三次基线中的精确率或召回率发生变化、关键场景失败，或者 p95 资源上限超标时，命令以非零状态退出。它不需要 Ollama、Gemini、OpenAI 或其他 API 密钥。

## 可执行场景集

[`scripts/leon-eval-ptbr-model.ts`](../../scripts/leon-eval-ptbr-model.ts) 中的规范注册表负责以下场景及其精确测试证据：

1. 使用 `memory_remember` 保留信息并在同一会话中检索。
2. 在同一 workspace 的第二个会话中检索显式记忆。
3. 重启本地提供方并保留持久记录。
4. 绝不跨 workspace 读取或变更。
5. 绝不为其他用户授权自动存储。
6. 更正一个精确的记忆 revision。
7. 拒绝过期 revision 冲突。
8. 遗忘已确认的记忆。
9. 拒绝 `memory_remember` 中的凭据。
10. 拒绝管理更正中的凭据。
11. 从回忆和审计遥测中省略类似凭据的搜索文本。
12. 仅把自动回忆作为无指令权的数据呈现。
13. 对无关的 PT-BR 消息不注入不相关记忆。
14. 让影子建议留在持久记忆之外。
15. 区分稳定事实、建议与假设。
16. 区分决定与偏好。
17. 保留 revision 历史。
18. 在没有已注册 workspace 时拒绝提取。
19. 从活动检索中排除已被取代的 revision。
20. 在启用替代记录时保留矛盾历史。
21. 在没有完整用户和 workspace 同意时阻止自动写入。
22. 强制执行回忆上下文硬预算。
23. 只向外部路由预检提供数值事实，绝不提供提示词或记忆内容。
24. 把已存提示词注入限制在不可信数据封装内。
25. 为短对话选择轻量本地 Qwen 层级。
26. 为中等技术任务提高本地推理强度。
27. 当外部路由被拒绝时关闭式失败。
28. 通过可选本地语义路径检索同义表达。
29. 绝不把其他 workspace 的记忆发送到语义端点。
30. 当语义 Ollama 端点不可用时回退到词法回忆。
31. 在部署接受基准之前保持语义检索为选择启用。

场景 4、5、23、24 和 29 为关键场景。它们的任何失败或证据缺失都会单独报告为硬失败。

## 指标

- **Oracle 精确率**是所有带有确定性预期输出标签的场景通过率。
- **Recall@k** 是回忆场景的通过率；其证据在配置边界内断言预期命中、省略、排序或回退。
- **误发现率**是 oracle 失败率，**回忆误报率**是明确无关输入场景的失败率。
- **跨 workspace、跨用户和敏感数据泄漏率**是相应安全场景组的失败率；接受值为零。
- **确认、拒绝、云端同意和提示词注入比率**是相应策略场景组的通过率。
- **p50 和 p95 延迟**对每个场景的精确证据耗时求和。默认 p95 目标为 2,000 ms。
- **p50 和 p95 堆内存**使用 Vitest 的逐测试堆内存诊断。默认 p95 目标为 512 MiB；报告也记录每次运行的进程 RSS。

报告只包含场景 id、PT-BR 标题、通过或失败状态、耗时和资源计数。它不包含提示词、记忆内容、workspace id、用户 id、凭据、模型响应或失败堆栈。

## 推进标准

- 至少三次完整基线运行。
- 每次运行中的所有场景证据均存在并通过。
- 各次基线运行中的 oracle 精确率与 Recall@k 保持稳定。
- 关键失败为零，跨 workspace、跨用户、敏感数据或未授权云端泄漏为零。
- p95 延迟与堆内存均在本地目标内。

## 解释限制

无需密钥的套件评估 Leon 的确定性运行时、本地提供方、Loader 组合、安全上下文和路由决定。路由场景证明 Leon 会选择哪个已配置路由与推理强度，并不声称模型回答质量。语义场景使用受控的 loopback 端点，因此在语义检索成为交付默认值之前，真实 Ollama 冷启动、GPU 吞吐量和 embedding 质量仍需要特定部署的硬件运行。
