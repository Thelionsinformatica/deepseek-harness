# 记忆 V2 — 搜索与检索

[English](memory-v2-retrieval.md) | 中文

## 目标

提供稳健、可审计且本地优先的检索，从现有词法搜索开始，逐步演进为本地混合检索。

## 检索层

1. **精确匹配**
   - 对精确 token 执行确定性匹配。
2. **词法搜索（当前）**
   - 当前 `memory-local` 实现会规范化词项并为其评分。
3. **本地语义搜索（未来阶段）**
   - 使用 `nomic-embed-text` 作为可选提供方。
   - 使用工作区、有效性与状态过滤器进行语义重排序。
4. **业务过滤器**
   - `workspaceId`、`userId`、`status`、时间有效性与 `sensitivity`。

## 建议管线

1. 根据用户消息构建查询。
2. 应用强制工作区过滤器。
3. 每次都执行字面与词法搜索。
4. 当本地语义搜索可用且产生有用分数时，可选择执行该搜索。
5. 按 `id` 合并并去重。
6. 按 `importance`、新近程度与可靠性确定优先级。
7. 根据策略与 token 预算限制结果。
8. 在 `MemoryContextComposer` 中公开检索原因。

## 上下文控制

- 使用有界上下文字符串，例如初始流程中的 1,000–3,000 个 token。
- 排除无效记忆：已过期、已被取代或 `status != active`。
- 绝不把记忆转换为指令；将其呈现为非特权上下文部分。

## 最低指标

- 查询命中率。
- 有效回忆率：结果在下一轮中被使用。
- 按类别统计的 Recall@k 与人工精度。
- 以毫秒计的查询 p95 延迟。
- 敏感数据误报率。
- 组合后每个会话减少的 token 数量。

## 搜索迁移

- 阶段 1：保持词法搜索为默认值，在收益未经证明时不阻塞发布。
- 阶段 2：仅当召回率或精度收益超过其延迟与运营成本时添加语义搜索。
