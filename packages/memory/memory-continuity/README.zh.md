# @deepseek-ai/dsh-memory-continuity

[English](README.md) | 中文

为本地记忆谱系记录提供可移植快照和幂等恢复。

## 消费方约定

调用方提供源域和目标表。本包不配置存储、不安排备份，也不暴露模型工具。它保留 memory-local 拥有的记录格式，无需 PostgreSQL 服务。

导出会验证记录并添加 SHA-256 校验和。同一快照的序列化结果稳定；除非指定导出时间，否则时间戳会变化。校验和用于检测损坏，不能阻止能够重新计算校验和的人恶意修改数据。快照包含明文记忆，访问控制由调用方负责。

导入在写入前验证完整快照以及所有目标名称和版本。重复的域名、目标名称以及同一域内重复的记录 ID 均被拒绝。每个缺失 ID 通过表的原子条件修改插入；已存在的 ID 即使内容不同也会跳过。

本包没有跨域事务。存储失败会以 `Memory import incomplete` 拒绝操作，先前的写入可能已经提交。修复存储后重试同一快照即可跳过已有记录。导入不会回滚或覆盖并发写入。目标必须实现 KvTable 修改约定。

## 日志和持久化

导入仅在成功后返回计数和日志条目。`exportJournal` 构造导出条目。两个函数都不持久化日志；持久追加、备份文件写入和恢复由调用方负责。重试的计数只描述本次尝试，不累计此前的尝试。

## 验证

写入中断示例在临时文件部分写入后以及原子重命名前后注入子进程终止。新的 Loader 进程重新打开预期的完整状态。终止后可能留下临时文件；该测试不实现自动残留清理，也不模拟物理断电。

重启场景还会在写入得到确认且快照导出后，以代码 73 立即退出，跳过插件释放。父进程验证正常关闭标记不存在，然后在新进程中重新打开记录。这测试的是提交后的进程终止，不是写入期间中断或物理断电。

`examples/headless-agent/memory-restart.cordis.yml` 磁盘重启示例在独立进程中使用编译后的 JSON 后端和域层。它验证正常退出进程后的谱系、恢复到新域、再次重启后的幂等性，以及拒绝格式错误的存储而不覆盖它。它不模拟断电或并发写入方。

`examples/headless-agent/memory-continuity.cordis.yml` 示例通过 Loader 加载编译后的插件。它的测试检查快照文件、导入计数、缺失目标的拒绝以及服务释放，无需调用模型 API。

专项测试覆盖谱系恢复、重复导入、无效校验和、写入前拒绝、模拟存储失败后的重试，以及内存表上的并发条件插入。重启和模型切换测试复用内存池；它不能证明真实模型切换、进程崩溃恢复或多进程磁盘并发。

在仓库根目录运行：

```sh
pnpm exec vitest run packages/memory/memory-continuity/tests/memory-continuity.spec.ts
pnpm exec tsc -b packages/memory/memory-continuity
```

## 模型体验

无，因为快照导出和恢复不注册模型工具或提示词段落。

#### KV Cache 影响

本包不组装或修改模型请求。检索及其对可复用请求前缀的影响由消费方负责。

## 已知限制与暂缓事项

- 本包不导出嵌入索引、不提供加密，也不实现安装程序。宿主必须显式选择域，并按需重建派生索引。
- 跨域回滚和日志持久化由调用方负责；导入和日志部分定义重试及持久性行为。
